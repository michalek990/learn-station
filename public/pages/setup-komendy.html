Style
Tailwind CSS v4 — nowy, prostszy sposób
ℹ Tailwind v4 od stycznia 2025 npm install tailwindcss instaluje teraz v4 domyślnie. W v4 nie ma tailwind.config.js ani komendy npx tailwindcss init — stąd błąd "could not determine executable to run". Konfiguracja przeniosła się do CSS i pluginu Vite.
terminal
# zainstaluj Tailwind v4 + oficjalny plugin dla Vite
$yarn add -D tailwindcss @tailwindcss/vite
# NIE uruchamiaj "npx tailwindcss init" — to komenda v3, w v4 nie istnieje
📄 vite.config.ts — dodaj import i plugin tailwindcss()
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite' // ← dodaj
export default defineConfig({
plugins: [react(), tailwindcss()], // ← dodaj tailwindcss()
})
📄 src/index.css — zastąp całą zawartość
@import "tailwindcss"; /* jedna linia zamiast trzech @tailwind */
/* CSS zmienne — shadcn uzupełni je automatycznie podczas init */
:root {
--background: 0 0% 100%;
--foreground: 222.2 84% 4.9%;
--primary: 221.2 83.2% 53.3%;
--muted: 210 40% 96.1%;
--border: 214.3 31.8% 91.4%;
}
4
Aliasy importów
Skonfiguruj @/ — zrób to PRZED shadcn
⚠ Kolejność krytyczna shadcn podczas init sprawdza czy aliasy istnieją. Brak aliasów = błąd "No import alias found in your tsconfig.json". Dlatego ten krok jest przed shadcn, nie po.
terminal
# potrzebny żeby path.resolve(__dirname) zadziałało w vite.config.ts
$yarn add -D @types/node
📄 tsconfig.json — dodaj compilerOptions z paths
{
"files": [],
"references": [
{ "path": "./tsconfig.app.json" },
{ "path": "./tsconfig.node.json" }
],
"compilerOptions": { // ← dodaj całą tę sekcję
"baseUrl": ".",
"paths": {
"@/*": ["./src/*"]
}
}
}
📄 tsconfig.app.json — dopisz baseUrl i paths do istniejącego compilerOptions
{
"compilerOptions": {
// ... reszta istniejących opcji bez zmian ...
"baseUrl": ".", // ← dodaj
"paths": { // ← dodaj
"@/*": ["./src/*"]
}
}
}
📄 vite.config.ts — pełna wersja z aliasami i Tailwind v4
import path from 'path'
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'
export default defineConfig({
plugins: [react(), tailwindcss()],
resolve: {
alias: {
'@': path.resolve(__dirname, './src'),
},
},
})
Dlaczego dwa pliki tsconfig? Vite 5+ dzieli konfigurację. tsconfig.json jest "koordynatorem" — shadcn szuka aliasów właśnie tutaj. tsconfig.app.json to właściwa konfiguracja kompilatora — potrzebuje aliasów żeby VSCode rozumiał @/components/… w importach i nie pokazywał czerwonych podkreśleń.

📄 .eslintrc.cjs — utwórz w root projektu
module.exports = {
root: true,
env: { browser: true, es2020: true },
extends: [
'eslint:recommended',
'plugin:@typescript-eslint/recommended',
'airbnb',
'airbnb-typescript',
'eslint-config-prettier', // musi być ostatni — wyłącza reguły kolidujące z Prettier
],
parser: '@typescript-eslint/parser',
parserOptions: { project: './tsconfig.json' },
rules: {
'no-console': ['warn', { allow: ['warn', 'error'] }],
'react/react-in-jsx-scope': 'off', // React 17+ — nie trzeba importować
'react/prop-types': 'off', // używamy TypeScript
'import/prefer-default-export': 'off',
'react/function-component-definition': [2, {
namedComponents: 'arrow-function', // tylko: const X = () => {}
}],
},
}

Formatowanie
Prettier — automatyczne formatowanie kodu
terminal
$yarn add -D prettier prettier-plugin-tailwindcss
📄 .prettierrc — utwórz w root projektu
{
"singleQuote": true, // 'tak' zamiast "tak"
"semi": true, // średniki na końcu linii
"tabWidth": 2, // 2 spacje wcięcia
"printWidth": 120, // max 120 znaków w linii
"trailingComma": "all", // przecinek po ostatnim elemencie
"useTabs": false,
"plugins": ["prettier-plugin-tailwindcss"] // auto-sortuje klasy Tailwinda
}
W VSCode zainstaluj rozszerzenie Prettier - Code formatter i dodaj do settings.json: "editor.formatOnSave": true — kod będzie formatowany automatycznie przy każdym Ctrl+S.

Testy
Vitest + Testing Library
terminal
$yarn add -D vitest @testing-library/react @testing-library/jest-dom @testing-library/user-event jsdom
# utwórz folder na testy
$mkdir src/tests
$touch src/tests/setup.ts
📄 vitest.config.ts — utwórz w root projektu
import { defineConfig, mergeConfig } from 'vitest/config'
import viteConfig from './vite.config'
// dziedziczy aliasy @/ z Vite — działają też w testach
export default mergeConfig(viteConfig, defineConfig({
test: {
globals: true, // describe/it/expect bez importu
environment: 'jsdom', // symuluje DOM przeglądarki
setupFiles: './src/tests/setup.ts',
},
}))
📄 src/tests/setup.ts
import '@testing-library/jest-dom'
// dzięki temu możesz pisać: expect(el).toBeInTheDocument()
10
Git Hooks
Husky + Commitlint
terminal
# upewnij się że masz git repo
$git init
# zainstaluj husky + commitlint
$yarn add -D husky @commitlint/cli @commitlint/config-conventional
# aktywuj husky
$npx husky install
# hook: blokuje commit gdy testy nie przechodzą
$npx husky add .husky/pre-commit "yarn run test"
# hook: sprawdza format wiadomości commita
$npx husky add .husky/commit-msg 'npx --no -- commitlint --edit "$1"'
📄 commitlint.config.cjs — utwórz w root projektu
module.exports = {
extends: ['@commitlint/config-conventional'],
}
// dozwolone formaty:
// feat: dodanie nowej funkcji
// fix: naprawienie błędu
// chore: aktualizacja zależności, konfiguracja
// refactor: przepisanie bez zmiany działania
// docs: dokumentacja
✅ Jak to działa git commit -m "feat: nowa strona" → uruchamia testy → sprawdza format → commit zapisany. Zły format lub padające testy = commit zablokowany.

// najczęściej używana funkcja w projekcie
