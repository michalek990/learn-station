01 / 12
Zanim zaczniesz
Czym jest React i po co w ogóle istnieje?
Wyobraź sobie że budujesz stronę internetową. Na początku masz tylko HTML. Ale co gdy chcesz żeby coś się zmieniało — koszyk w sklepie, licznik lajków, powiadomienia? Tutaj wkracza React. To biblioteka JavaScript która sprawia że strona "żyje" i reaguje na działania użytkownika — stąd nazwa React (reagować).
🧱
HTML = szkielet
HTML to suchy tekst który przeglądarka wyświetla. Możesz napisać <button>Kliknij</button> — ale po kliknięciu nic się nie stanie bez dodatkowego kodu.
⚙️
JavaScript = silnik
JavaScript to kod który sprawia że strona reaguje. Problem: gdy aplikacja rośnie, ręczne zarządzanie zmianami w HTML staje się koszmarnie skomplikowane.
⚛️
React = inteligentny silnik
React zarządza tym za Ciebie. Opisujesz jak ma wyglądać interfejs w danym stanie. React sam oblicza co się zmieniło i aktualizuje tylko to co trzeba.
❌ Bez React — bałagan
Masz 500 elementów na stronie. Użytkownik klika "dodaj do koszyka". Musisz ręcznie znaleźć element koszyka w HTML, zmienić liczbę, zmienić kolor przycisku, ukryć komunikat "koszyk pusty", pokazać komunikat "1 produkt"... i pamiętać żeby zrobić to we wszystkich miejscach. Gdy coś pójdzie nie tak — debugging to koszmar.
✅ Z React — porządek
Mówisz React: "stan koszyka to 3 produkty". React sam decyduje jak wyświetlić licznik, przycisk, komunikat. Gdy dodajesz produkt, zmieniasz jeden stan — React automatycznie aktualizuje wszystkie miejsca które od niego zależą. Zawsze spójnie.
💡
Kluczowa idea React w jednym zdaniu: Zamiast mówić przeglądarce "zmień ten element", mówisz React "w tym stanie aplikacja powinna wyglądać tak" — i React sam zajmuje się zmianami. To podejście nazywa się deklaratywne (opisujesz CO, nie JAK).

Serce Reacta
Komponenty — klocki LEGO z których budujesz interfejs
Komponent to kawałek interfejsu — może to być przycisk, nagłówek, karta produktu, cały formularz, a nawet cała strona. Każdy komponent to osobna, niezależna jednostka. Składasz je jak klocki LEGO — mały przycisk wchodzi w kartę, karta wchodzi w listę, lista wchodzi w stronę.
🧩
Reużywalność
Jeden komponent <Button> — używasz go 50 razy w całej aplikacji. Zmienisz raz — zmieni się wszędzie.
📦
Izolacja
Każdy komponent ma swój kod, styl i logikę. Błąd w jednym nie psuje innych.
🗂️
Organizacja
Każdy komponent w osobnym pliku. Łatwo znaleźć co szukasz w dużym projekcie.

// Komponent to funkcja która zwraca JSX (HTML-like kod)
// Nazwa MUSI zaczynać się od WIELKIEJ litery!

function Powitanie() {
  return (
    <div>
      <h1>Cześć! 👋</h1>
      <p>Witaj w moim pierwszym komponencie React!</p>
    </div>
  );
}

// Albo jako arrow function (to samo!):
const Powitanie = () => {
  return <h1>Cześć! 👋</h1>;
};

// Używasz go jak tag HTML — ale z WIELKĄ literą:
function App() {
  return (
    <div>
      <Powitanie />   ← używasz jak tag!
      <Powitanie />   ← możesz wiele razy!
      <Powitanie />
    </div>
  );
}

// Eksportowanie — żeby użyć w innych plikach:
export default Powitanie;

// W innym pliku:
import Powitanie from "./Powitanie";
⚠️ Reguła nr 1 — zapamiętaj na zawsze Nazwa komponentu musi zaczynać się od wielkiej litery. <button> to zwykły HTML. <Button> to komponent React. React rozróżnia je właśnie po tej literze. Pisanie function mojaFunkcja() i używanie jako <mojaFunkcja /> nie zadziała — React potraktuje to jako nieznany tag HTML.

Składnia
JSX — HTML wewnątrz JavaScript (tak, to nie pomyłka)
Gdy po raz pierwszy widzisz JSX, myślisz: "moment, to jest HTML w środku JavaScript?!". Tak — i to celowo. JSX to specjalna składnia która wygląda jak HTML, ale jest tak naprawdę JavaScript. Przeglądarka tego nie rozumie bezpośrednio — narzędzie o nazwie Babel tłumaczy JSX na zwykłe wywołania JavaScript zanim kod trafi do przeglądarki.
JSX — podstawowe zasady
// ─── Zasada 1: Jeden element root ────────────────────────
// ❌ Błąd — dwa elementy obok siebie:
return (
  <h1>Tytuł</h1>
  <p>Tekst</p>
);

// ✅ Opakuj w jeden element:
return (
  <div>
    <h1>Tytuł</h1>
    <p>Tekst</p>
  </div>
);

// ✅ Albo użyj Fragment (puste tagi <>) — nie dodaje div do HTML:
return (
  <>
    <h1>Tytuł</h1>
    <p>Tekst</p>
  </>
);

// ─── Zasada 2: Tagi muszą być zamknięte ──────────────────
// ❌ W HTML możesz: <input> lub <br>
// ✅ W JSX musisz: <input /> lub <br />

// ─── Zasada 3: class → className ─────────────────────────
// ❌ <div class="box"> — class to słowo kluczowe JS!
<div className="box">...</div>  // ✅

// ─── Zasada 4: for → htmlFor ─────────────────────────────
<label htmlFor="email">Email:</label>  // ✅
JSX — wyrażenia JavaScript wewnątrz {}
// {} pozwala wstawić dowolne wyrażenie JS do JSX

const imie = "Anna";
const wiek = 28;
const zalogowany = true;

return (
  <div>
    { /* Zmienne: */ }
    <h1>Cześć, {imie}!</h1>
    <p>Masz {wiek} lat</p>

    { /* Wyrażenia matematyczne: */ }
    <p>Za rok będziesz mieć {wiek + 1} lat</p>

    { /* Wywołania funkcji: */ }
    <p>{imie.toUpperCase()}</p>

    { /* Operator trójkowy (if-else): */ }
    <p>{zalogowany ? "Zalogowany ✅" : "Niezalogowany ❌"}</p>

    { /* Styl inline — obiekt JS: */ }
    <p style={{ color: "red", fontSize: "20px" }}>
      Czerwony tekst
    </p>
    { /* ↑ Dwie klamry: zewnętrzna = "tu jest JS",
         wewnętrzna = obiekt JS z właściwościami CSS */ }

    { /* Komentarz w JSX: */ }
    {/* To jest komentarz — nie widać go na stronie */}
  </div>
);

// ❌ W {} NIE możesz pisać: if, for, while (to statements)
// ✅ Możesz: wyrażenia, funkcje, ternary, &&, metody tablic

Dane między komponentami
Props — jak przekazać dane do komponentu
Props (skrót od properties) to sposób przekazywania danych do komponentu — jak argumenty do funkcji. Dzięki propsom jeden komponent <KartaUzytkownika> może wyświetlać różnych użytkowników zależnie od tego co do niego przekażesz. Bez propsów każdy komponent byłby identyczną kopią.
Props — przekazywanie i odbieranie
// ─── Przekazywanie propsów (rodzic → dziecko) ────────────
function App() {
  return (
    <div>
      { /* Przekazujesz propsy jak atrybuty HTML: */ }
      <Karta
        imie="Anna"
        wiek={28}
        zalogowana={true}
        kolory={["niebieski", "zielony"]}
      />
      <Karta
        imie="Marek"
        wiek={35}
        zalogowana={false}
        kolory={["czerwony"]}
      />
    </div>
  );
}

// ─── Odbieranie propsów (komponent dziecko) ──────────────
function Karta(props) {
  // props to obiekt ze wszystkimi przekazanymi wartościami
  return (
    <div>
      <h2>{props.imie}</h2>
      <p>Wiek: {props.wiek}</p>
      <p>Status: {props.zalogowana ? "✅" : "❌"}</p>
    </div>
  );
}

// ─── Krócej — destructuring propsów ──────────────────────
function Karta({ imie, wiek, zalogowana }) {
  // wyciągasz od razu po nazwach — czytelniej!
  return (
    <div>
      <h2>{imie}</h2>
      <p>Wiek: {wiek}</p>
    </div>
  );
}
Domyślne wartości i prop children
// ─── Wartości domyślne ────────────────────────────────────
function Przycisk({ tekst = "Kliknij", kolor = "blue" }) {
  return (

      {tekst}

<Przycisk />                    // "Kliknij", niebieski
<Przycisk tekst="Wyślij" />     // "Wyślij", niebieski
<Przycisk tekst="Usuń" kolor="red" /> // "Usuń", czerwony

// ─── Specjalny prop: children ─────────────────────────────
// children = wszystko co wpisujesz MIĘDZY tagami
function Ramka({ children }) {
  return (
    <div style={{ border: "2px solid blue", padding: "16px" }}>
      {children}   ← renderuje zawartość między tagami
    </div>
  );
}

// Użycie:
<Ramka>
  <h2>To jest w środku ramki</h2>
  <p>Dowolna zawartość!</p>
</Ramka>
🔒 Kluczowa zasada propsów
Props są tylko do odczytu. Komponent który dostaje propsy NIE może ich modyfikować. Dane płyną zawsze w jednym kierunku: od rodzica do dziecka. Nigdy odwrotnie.

Interaktywność
Stan (State) — pamięć komponentu która powoduje re-render
Props to dane z zewnątrz. Stan to wewnętrzna pamięć komponentu — rzeczy które się zmieniają w czasie (licznik kliknięć, czy menu jest otwarte, co wpisał użytkownik w formularzu). Gdy stan się zmienia, React automatycznie przerendrowuje komponent — wyświetla aktualną wartość. To jest magia Reacta.
useState — podstawowy hook stanu
// Importujesz useState z React:
import { useState } from "react";

function Licznik() {
  // useState(0) — zaczynamy od wartości 0
  // count     — aktualna wartość stanu
  // setCount  — funkcja do zmiany stanu
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Kliknięcia: {count}</p>

      <button onClick={() => setCount(count + 1)}>
        Dodaj +1
      </button>

      <button onClick={() => setCount(count - 1)}>
        Odejmij -1
      </button>

      <button onClick={() => setCount(0)}>
        Reset
      </button>
    </div>
  );
}

// ─── Inne typy stanu ──────────────────────────────────────
const [imie, setImie]           = useState("");         // string
const [zalogowany, setZalogow] = useState(false);     // boolean
const [lista, setLista]         = useState([]);          // tablica
const [user, setUser]           = useState(null);       // obiekt/null
const [tryb, setTryb]           = useState("light");   // string-enum
Stan obiektów i tablic
// ─── Stan jako obiekt ─────────────────────────────────────
const [user, setUser] = useState({
  imie: "Anna",
  wiek: 28
});

// ❌ NIE rób tak — bezpośrednia mutacja:
user.imie = "Marek";   // React nie zauważy zmiany!

// ✅ Stwórz nowy obiekt ze spread operator:
setUser({ ...user, imie: "Marek" });
// ...user kopiuje wszystkie pola, imie nadpisuje

// ─── Stan jako tablica ────────────────────────────────────
const [lista, setLista] = useState(["a", "b"]);

// ✅ Dodaj element:
setLista([...lista, "c"]);           // ["a","b","c"]

// ✅ Usuń element (po indeksie):
setLista(lista.filter((_, i) => i !== 1)); // ["a","c"]

// ✅ Zmień element:
setLista(lista.map((el, i) =>
  i === 0 ? "X" : el               // ["X","b"]
));
🚨 Pułapka nr 1 Nigdy nie zmieniaj stanu bezpośrednio! Zawsze używaj funkcji setState. Gdy modyfikujesz obiekt lub tablicę, stwórz nową kopię. React wykrywa zmiany porównując referencje — jeśli zmodyfikujesz oryginalny obiekt, React pomyśli że nic się nie zmieniło i nie przerendrowuje.
🧠
Jak myśleć o stanie?
Stan to minimalne informacje które musi pamiętać komponent żeby wiedzieć jak się wyświetlić. Nie trzymaj w stanie rzeczy które możesz obliczyć z innych danych.
🔄
Re-render = odświeżenie
Gdy wywołujesz setState, React uruchamia funkcję komponentu od nowa i porównuje wynik z poprzednim. Aktualizuje tylko to co się zmieniło w DOM.
📍
Stan jest lokalny
Stan żyje w konkretnym komponencie. Inne komponenty nie widzą jego stanu (chyba że przekażesz go przez propsy lub użyjesz globalnego stanu).
06 / 12
Efekty uboczne
useEffect — co robić po renderze (API, timery, subskrypcje)
useEffect służy do wykonywania rzeczy które dzieją się "obok" renderowania — pobieranie danych z API, ustawianie timera, nasłuchiwanie na zdarzenia, zmiana tytułu strony. Tych rzeczy nie można robić bezpośrednio podczas renderowania — muszą poczekać aż komponent pojawi się na stronie.
useEffect — trzy formy
import { useState, useEffect } from "react";

function MojKomponent() {
  const [dane, setDane] = useState(null);

  // ─── Forma 1: Bez dependency array ───────────────────────
  // Uruchamia się PO KAŻDYM renderze
  useEffect(() => {
    console.log("Komponent się wyrenderował!");
  }); ← brak []

  // ─── Forma 2: Pusta tablica [] ────────────────────────────
  // Uruchamia się TYLKO RAZ — gdy komponent pojawia się na stronie
  useEffect(() => {
    // Idealne do pobierania danych przy starcie:
    fetch("https://api.example.com/dane")
      .then(res => res.json())
      .then(data => setDane(data));
  }, []); ← pusta tablica = tylko raz

  // ─── Forma 3: Z zależnościami ─────────────────────────────
  // Uruchamia się gdy zmieni się wartość w tablicy
  const [userId, setUserId] = useState(1);

  useEffect(() => {
    fetch(`https://api.example.com/user/${userId}`)
      .then(res => res.json())
      .then(data => setDane(data));
  }, [userId]); ← uruchom gdy userId się zmieni

  return <div>{dane ? dane.imie : "Ładowanie..."}</div>;
}
useEffect — funkcja cleanup (sprzątanie)
// Czasem useEffect tworzy rzeczy które trzeba posprzątać
// gdy komponent znika ze strony (unmount)

function Zegar() {
  const [czas, setCzas] = useState(new Date());

  useEffect(() => {
    // Uruchamiamy timer
    const timer = setInterval(() => {
      setCzas(new Date());
    }, 1000);

    // Zwracamy funkcję cleanup — React wywoła ją:
    // - gdy komponent znika ze strony
    // - przed następnym uruchomieniem tego efektu
    return () => {
      clearInterval(timer); ← wyczyść timer!
    };
  }, []); ← tylko raz przy mount

  return <p>{czas.toLocaleTimeString()}</p>;
}

// Bez cleanup: timer działałby nadal po usunięciu komponentu
// = wyciek pamięci (memory leak) i błędy w konsoli

// ─── Kolejność wykonania ──────────────────────────────────
// 1. React renderuje komponent (zwraca JSX)
// 2. React aktualizuje DOM
// 3. TERAZ useEffect się uruchamia
// 4. (gdy stan się zmieni → wróć do 1)

Renderowanie danych
Listy i klucze — wyświetlanie wielu elementów naraz
Aplikacje rzadko wyświetlają pojedyncze elementy — zwykle listy produktów, komentarzy, użytkowników. W React listy renderujesz przez metodę .map() — przekształcasz tablicę danych w tablicę elementów JSX. Każdy element musi mieć unikalny atrybut key — React używa go do śledzenia co się zmieniło.
Renderowanie listy przez .map()
function ListaOwoców() {
  const owoce = ["🍎 Jabłko", "🍌 Banan", "🍊 Pomarańcza"];

  return (
    <ul>
      {owoce.map((owoc, index) => (
        <li key={index}>{owoc}</li>
      ))}
    </ul>
  );
}

// ─── Realistyczny przykład z obiektami ───────────────────
function ListaUzytkownikow() {
  const uzytkownicy = [
    { id: 1, imie: "Anna",  email: "anna@example.com"  },
    { id: 2, imie: "Marek", email: "marek@example.com" },
    { id: 3, imie: "Kasia", email: "kasia@example.com" },
  ];

  return (
    <div>
      {uzytkownicy.map(user => (
        <KartaUzytkownika
          key={user.id}          ← ZAWSZE unikalny key!
          imie={user.imie}
          email={user.email}
        />
      ))}
    </div>
  );
}

function KartaUzytkownika({ imie, email }) {
  return (
    <div style={{ border: "1px solid #ccc", padding: "12px" }}>
      <h3>{imie}</h3>
      <p>{email}</p>
    </div>
  );
}
Klucze — dlaczego są ważne
// key pomaga React śledzić które elementy się zmieniły

// ❌ Zły key — indeks tablicy:
{lista.map((item, index) => (
  <Item key={index} data={item} />
))}
// Problem: gdy dodajesz/usuwasz elementy,
// indeksy się zmieniają → React myli elementy
// → utrata stanu formularzy, błędne animacje

// ✅ Dobry key — unikalny, stały identyfikator:
{lista.map(item => (
  <Item key={item.id} data={item} />
))}
// id nigdy się nie zmienia → React wie co to co

// ─── Filtrowanie listy przed renderem ────────────────────
const [szukaj, setSzukaj] = useState("");

const przefiltrowane = uzytkownicy.filter(u =>
  u.imie.toLowerCase().includes(szukaj.toLowerCase())
);

// Renderuj przefiltrowaną listę:
{przefiltrowane.map(user => (
  <KartaUzytkownika key={user.id} {...user} />
))}
⚠️ Klucze — złota reguła Używaj key={item.id} gdy masz ID z bazy danych. Używaj key={index} tylko gdy lista nigdy się nie zmienia (nie dodajesz, nie usuwasz, nie resortujesz). Klucz nie jest dostępny przez propsy — jest tylko dla Reacta.

Interakcja
Obsługa zdarzeń — kliknięcia, najechanie, klawiatura
Zdarzenia w React działają podobnie jak w HTML — ale nazwy są camelCase (onClick zamiast onclick), a jako wartość przekazujesz funkcję (nie wywołanie funkcji!). React opakowuje natywne zdarzenia przeglądarki w swój "SyntheticEvent" — działa tak samo, ale spójnie we wszystkich przeglądarkach.
Obsługa zdarzeń — podstawy
function Przyciski() {
  // ─── Sposób 1: funkcja inline (prosta logika) ─────────
  return (
    <button onClick={() => alert("Kliknięto!")}>
      Kliknij mnie
    </button>
  );
}

function Przyciski2() {
  // ─── Sposób 2: nazwana funkcja (lepsza przy złożonej logice)
  const handleClick = () => {
    console.log("Kliknięto!");
    // możesz tu pisać dużo logiki
  };

  const handleMouseEnter = () => {
    console.log("Najechano kursorem!");
  };

  return (
    <div>
      <button onClick={handleClick}>Kliknij</button>

      <button onMouseEnter={handleMouseEnter}>Najedź</button>
    </div>
  );
}

// ─── WAŻNE: przekazujesz funkcję, nie jej wywołanie! ─────
// ✅ onClick={handleClick}     — OK, przekazujesz funkcję
// ❌ onClick={handleClick()}   — ŹLE! Wywołujesz od razu!
//    (nawias () wywołuje funkcję przy renderze, nie przy kliknięciu)

// ─── Przekazywanie argumentów ────────────────────────────
// Gdy chcesz przekazać argument — opakuj w arrow function:
{produkty.map(p => (
  <button key={p.id} onClick={() => usun(p.id)}>Usuń</button>
))}
Zdarzenie (event) i zapobieganie domyślnemu
// Każdy handler otrzymuje obiekt zdarzenia (event):
const handleClick = (event) => {
  console.log(event.target);     // element który kliknięto
  console.log(event.type);       // "click"

Dane od użytkownika
Formularze — jak zbierać i obsługiwać dane od użytkownika
Formularze w React działają przez "controlled components" — każdy input ma swoją wartość zapisaną w stanie React, i aktualizuje się przez onChange. React jest jedynym źródłem prawdy o wartości inputa — stąd nazwa "controlled" (kontrolowany).
Controlled Input — podstawowy wzorzec
import { useState } from "react";

function FormularzLogowania() {
  // Każde pole = osobny stan
  const [email, setEmail]       = useState("");
  const [haslo, setHaslo]       = useState("");
  const [blad, setBlad]         = useState("");

  const handleSubmit = (e) => {
    e.preventDefault();         ← zatrzymaj przeładowanie!

    // Walidacja
    if (!email || !haslo) {
      setBlad("Wypełnij wszystkie pola");
      return;
    }

    // Dane do wysłania:
    console.log({ email, haslo });
    // fetch("/api/login", { method: "POST", body: ... })
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <label>Email:</label>
        <input
          type="email"
          value={email}            ← React kontroluje wartość
          onChange={(e) => setEmail(e.target.value)} ← aktualizuj stan
          placeholder="twoj@email.pl"
        />
      </div>

      <div>
        <label>Hasło:</label>
        <input
          type="password"
          value={haslo}
          onChange={(e) => setHaslo(e.target.value)}
        />
      </div>

      {blad && <p style={{ color: "red" }}>{blad}</p>}

      <button type="submit">Zaloguj się</button>
    </form>
  );
}

Logika wyświetlania
Warunkowe renderowanie — pokazuj i chowaj elementy
Nie zawsze chcesz wyświetlać wszystko. Spinner ładowania tylko gdy czekasz na dane, komunikat błędu tylko gdy coś pójdzie nie tak, menu tylko gdy jest otwarte. W React masz kilka sposobów na warunkowe renderowanie — każdy do innych sytuacji.
5 wzorców warunkowego renderowania
function Przyklad({ isLoading, error, user, isAdmin }) {

  // ─── 1. If/else przed return — dla złożonej logiki ───────
  if (isLoading) return <Spinner />;
  if (error)     return <Error message={error} />;

  return (
    <div>

      {/* 2. Operator && — pokaż TYLKO gdy warunek true */}
      {isAdmin && <AdminPanel />}
      {user.verified && <span>✅ Zweryfikowany</span>}

      {/* 3. Operator trójkowy ? : — jedno LUB drugie */}
      {user ? <UserInfo user={user} /> : <LoginPrompt />}

      {/* 4. Null — nic nie renderuj */}
      {error ? <ErrorBox /> : null}

      {/* 5. Zmienna przechowująca JSX */}
      {(() => {
        if (user.rola === "admin")  return <AdminBadge />;
        if (user.rola === "mod")    return <ModBadge />;
        return <UserBadge />;
      })()}
    </div>
  );
}
Praktyczny przykład — Loading / Error / Data
function ListaPostow() {
  const [posty, setPosty]       = useState([]);
  const [laduje, setLaduje]     = useState(true);
  const [blad, setBlad]         = useState(null);

  useEffect(() => {
    fetch("https://jsonplaceholder.typicode.com/posts")
      .then(r => r.json())
      .then(data => {
        setPosty(data.slice(0, 5));
        setLaduje(false);
      })
      .catch(err => {
        setBlad(err.message);
        setLaduje(false);
      });
  }, []);

  // Trzy stany — każdy inny widok:
  if (laduje) return <p>⏳ Ładuję posty...</p>;
  if (blad)   return <p style={{color:"red"}}>❌ {blad}</p>;
  if (posty.length === 0) return <p>Brak postów</p>;

  return (
    <ul>
      {posty.map(post => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
💡 Pułapka z && {liczba && <Komponent />} — gdy liczba to 0, React wyrenderuje samo 0 na stronie (bo 0 jest falsy ale nie null/undefined)! Bezpieczniej: {liczba > 0 && <Komponent />} lub {!!liczba && <Komponent />}.

Architektura
Drzewo komponentów — jak dane przepływają w górę i w dół
Gdy budujesz aplikację React, dane naturalnie płyną z góry na dół — od rodzica przez propsy do dzieci. Ale co gdy dziecko chce zmienić stan rodzica? Przekazujesz funkcję jako prop. Gdy dwa różne komponenty potrzebują tego samego stanu, "winda go w górę" do wspólnego rodzica — to wzorzec zwany lifting state up.
Lifting state up — stan w górę do rodzica
// Problem: dwa komponenty chcą wiedzieć o tym samym

// ─── Rozwiązanie: stan w wspólnym rodzicu ─────────────────
function App() {
  // Stan jest TU — w rodzicu który widzi oba dzieci
  const [koszyk, setKoszyk] = useState([]);

  const dodajDoKoszyka = (produkt) => {
    setKoszyk(prev => [...prev, produkt]);
  };

  return (
    <div>
      { /* Dziecko 1: wyświetla produkty, przekazuje funkcję */ }
      <ListaProduktow onDodaj={dodajDoKoszyka} />

      { /* Dziecko 2: wyświetla koszyk */ }
      <Koszyk produkty={koszyk} />
    </div>
  );
}

function ListaProduktow({ onDodaj }) {
  const produkty = [
    { id: 1, nazwa: "Laptop", cena: 3000 },
    { id: 2, nazwa: "Mysz",   cena: 150  },
  ];
  return (
    <ul>
      {produkty.map(p => (
        <li key={p.id}>
          {p.nazwa} - {p.cena} zł
          { /* Wywołuje funkcję rodzica */ }
          <button onClick={() => onDodaj(p)}>Dodaj 🛒</button>
        </li>
      ))}
    </ul>
  );
}

function Koszyk({ produkty }) {
  const suma = produkty.reduce((s, p) => s + p.cena, 0);
  return (
    <div>
      <h3>Koszyk ({produkty.length})</h3>
      <p>Suma: {suma} zł</p>
    </div>
  );
}
