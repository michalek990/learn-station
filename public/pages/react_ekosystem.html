shadcn/ui
ui.shadcn.com ↗
Mid

Czym jest: Kolekcja pięknych, dostępnych komponentów opartych na Radix UI + Tailwind CSS. Ale zamiast instalować bibliotekę, kopiujesz kod komponentu bezpośrednio do swojego projektu — możesz go dowolnie modyfikować.

Filozofia: "Not a component library" — to zestaw wzorców do kopiowania. Pełna kontrola nad kodem, zero vendor lock-in.

Kiedy używać: Projekty z Tailwind CSS gdzie chcesz mieć kontrolę nad stylem. Startup / MVP gdzie estetyka ma znaczenie. Idealny do projektów Next.js.

Wymaga: Tailwind CSS, znajomości Radix UI (powierzchownie).

CSS Framework
Tailwind CSS — stylowanie przez klasy, bez pisania CSS
Tailwind to utility-first CSS framework — zamiast pisać własne klasy CSS, stosujesz gotowe klasy bezpośrednio w HTML/JSX. flex, p-4, text-blue-500, hover:bg-gray-100 — wszystko w atrybucie className. Na początku wygląda dziwnie, po tygodniu nie chcesz wracać do CSS.
Podstawowe klasy — skrótowy przewodnik
// ─── Layout ───────────────────────────────────────────────
// flex          → display: flex
// grid          → display: grid
// hidden        → display: none
// block         → display: block
// items-center  → align-items: center
// justify-between → justify-content: space-between
// gap-4         → gap: 16px (4 × 4px base unit)
// grid-cols-3   → grid-template-columns: repeat(3, 1fr)

// ─── Spacing (4px base unit) ──────────────────────────────
// p-4 → padding: 16px         m-4 → margin: 16px
// px-4 → padding left+right   py-2 → padding top+bottom
// pt-2, pr-4, pb-8, pl-1      mt-auto, mx-auto (center!)
// Skala: 1=4px, 2=8px, 4=16px, 6=24px, 8=32px, 16=64px

// ─── Sizing ──────────────────────────────────────────────
// w-full → width: 100%    h-screen → height: 100vh
// w-1/2  → width: 50%     max-w-lg → max-width: 32rem
// min-h-0                 overflow-hidden

// ─── Responsive prefixes ─────────────────────────────────
// sm:flex-col  → mobile-first: od sm (640px) flex-col
// md:grid-cols-2  lg:grid-cols-4  xl:hidden
// Breakpoints: sm=640px, md=768px, lg=1024px, xl=1280px

// ─── Przykład komponentu ─────────────────────────────────
<div className="flex items-center justify-between p-4 bg-white rounded-lg shadow-md hover:shadow-lg transition-shadow">
  <h2 className="text-xl font-bold text-gray-900">Tytuł</h2>
  <button className="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600 active:scale-95">
    Kliknij
  </button>
</div>

function cn(...inputs) {
  return twMerge(clsx(inputs));
}

  className  // z propsów — nadpisuje przez twMerge

HTTP Client
Axios — wysyłanie requestów HTTP
Axios to biblioteka do wykonywania requestów HTTP (GET, POST, PUT, DELETE...) — alternatywa dla wbudowanego fetch(). Daje automatyczną serializację JSON, interceptory, obsługę błędów, timeout i anulowanie requestów — czyli wszystko czego brakowało w czystym fetch.
Axios — podstawy i konfiguracja
// npm install axios

import axios from "axios";

// ─── Podstawowe żądania ───────────────────────────────────
const res = await axios.get("/api/users");
console.log(res.data);       // JSON automatycznie sparsowany
console.log(res.status);     // 200
console.log(res.headers);    // nagłówki odpowiedzi

await axios.post("/api/users", { name: "Anna", email: "..." });
await axios.put(`/api/users/${id}`, updatedData);
await axios.delete(`/api/users/${id}`);
await axios.patch(`/api/users/${id}`, { name: "Nowe imię" });

// ─── Axios Instance — konfiguracja globalna ───────────────
// Stwórz w: src/api/axiosInstance.js
const api = axios.create({
  baseURL: "https://api.mojaplikacja.pl",
  timeout: 10000,           // 10 sekund timeout
  headers: {
    "Content-Type": "application/json"
  }
});

// Teraz wszystkie requesty używają base URL:
await api.get("/users");     // → GET https://api.mojaplikacja.pl/users
export default api;
Interceptory — automatyczne tokeny i obsługa błędów
// ─── Request Interceptor — dodaj token do każdego żądania ─
api.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem("token");
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// ─── Response Interceptor — globalna obsługa błędów ──────
api.interceptors.response.use(
  (response) => response,       // sukces — zwróć normalnie
  (error) => {
    if (error.response?.status === 401) {
      // Wygasł token → wyloguj użytkownika
      localStorage.removeItem("token");
      window.location.href = "/login";
    }
    if (error.response?.status === 500) {
      toast.error("Błąd serwera — spróbuj ponownie");
    }
    return Promise.reject(error);
  }
);

// ─── Obsługa błędów w komponencie ────────────────────────
try {
  const { data } = await api.get("/users");
  setUsers(data);
} catch (error) {
  if (axios.isAxiosError(error)) {
    // Mamy odpowiedź serwera z błędem (4xx, 5xx)
    console.error(error.response?.data?.message);
  } else {
    // Błąd sieci, timeout, inne
    console.error("Network error");
  }
}
🔄 Axios vs fetch Wbudowany fetch() nie rzuca błędu przy statusach 4xx/5xx — musisz sprawdzać response.ok ręcznie. Axios robi to automatycznie. Dodatkowo Axios ma: automatyczny JSON parse/stringify, interceptory, timeout z pudełka, i lepszy TypeScript support. W 2024 fetch() jest w pełni wystarczający dla prostych projektów, ale Axios nadal dominuje w większych aplikacjach.

Synchronizacja Danych
React Query — dane z serwera pod kontrolą
React Query (TanStack Query) rozwiązuje jeden problem: zarządzanie stanem danych z serwera. Bez niego musisz ręcznie: pobierać dane, śledzić loading/error, cachować, odświeżać, invalidować. React Query robi to wszystko automatycznie. To nie zastępstwo Redux — to zupełnie inne narzędzie do innego problemu.
useQuery — pobieranie danych
// npm install @tanstack/react-query

// ─── Setup — Provider w głównym pliku ────────────────────
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000,   // 5 minut — kiedy dane są "świeże"
      retry: 2,                   // ponów żądanie 2 razy przy błędzie
    }
  }
});

function Root() {
  return (
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  );
}

// ─── useQuery — pobieranie danych ────────────────────────
function UserProfile({ userId }) {
  const { data: user, isLoading, isError, error } = useQuery({
    queryKey: ["user", userId],       // klucz cache'a
    queryFn: () => api.get(`/users/${userId}`).then(r => r.data),
  });

  if (isLoading) return <Spinner />;
  if (isError)   return <Error message={error.message} />;
  return <div>{user.name}</div>;
}
// React Query automatycznie: cache, re-fetch przy focus,
// deduplikuje identyczne żądania, odświeża w tle
useMutation — zapis danych + invalidation
// ─── useMutation — modyfikacja danych ────────────────────
import { useMutation, useQueryClient } from "@tanstack/react-query";

function EditUser({ userId }) {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: (data) => api.put(`/users/${userId}`, data),

    onSuccess: () => {
      // Zainvaliduj cache — React Query pobierze dane na nowo
      queryClient.invalidateQueries({ queryKey: ["user", userId] });
      queryClient.invalidateQueries({ queryKey: ["users"] }); // lista
      toast.success("Zapisano!");
    },
    onError: (error) => {
      toast.error(`Błąd: ${error.message}`);
    }
  });

  return (
    <form onSubmit={e => {
      e.preventDefault();
      mutation.mutate({ name: e.target.name.value });
    }}>
      <input name="name" />
      <button disabled={mutation.isPending}>
        {mutation.isPending ? "Zapisuję..." : "Zapisz"}
      </button>
    </form>
  );
}

Routing
React Router 6 — nawigacja w aplikacji SPA
React Router to standardowe rozwiązanie routingu dla aplikacji React (Single Page Application). Decyduje który komponent wyświetlić na podstawie adresu URL w przeglądarce. Wersja 6 przyniosła duże zmiany — głównie useNavigate zamiast useHistory, i nowe <Outlet> dla nested routes.
React Router 6 — podstawy
// npm install react-router-dom

// ─── Setup w głównym pliku ────────────────────────────────
import { BrowserRouter, Routes, Route, Link, NavLink }
  from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <nav>
        <NavLink to="/"
          className={({ isActive }) => isActive ? "active" : ""}>
          Home
        </NavLink>
        <Link to="/about">About</Link>
      </nav>

      <Routes>
        <Route path="/"           element={<Home />} />
        <Route path="/about"      element={<About />} />
        <Route path="/users/:id"  element={<UserDetail />} />
        <Route path="*"           element={<NotFound />} />
      </Routes>
    </BrowserRouter>
  );
}

// ─── Hooki ────────────────────────────────────────────────
const { id } = useParams();         // :id z URL
const navigate = useNavigate();
navigate("/dashboard");             // programowa nawigacja
navigate(-1);                        // cofnij (jak back)
const location = useLocation();      // aktualny URL, state
const [params] = useSearchParams(); // ?key=value
params.get("tab");                  // "settings"

function DashboardLayout() {
  return (
    <div className="flex">
      <Sidebar />

        <Outlet />   {/* tutaj renderuje się aktualna pod-strona */}
      </main>
    </div>

// ─── Protected Route — sprawdź auth przed renderem ───────
function ProtectedRoute({ children }) {
  const { isLoggedIn } = useAuth();
  const location = useLocation();

  if (!isLoggedIn) {
    // Zapisz gdzie user chciał iść, żeby wrócić po loginie
    return <Navigate to="/login" state={{ from: location }} replace />;
  }
  return children;
}

Kontener Stanu
Redux — globalny stan aplikacji, akcje i reducery
Redux to jeden z pierwszych i nadal popularnych sposobów na globalny stan w React. Opiera się na trzech filarach: Store (jeden globalny obiekt stanu), Actions (zdarzenia opisujące "co się stało"), Reducers (czyste funkcje obliczające nowy stan). Dziś używaj Redux Toolkit (RTK) — oficjalne narzędzie które eliminuje 80% boilerplate'u.
Redux Toolkit — createSlice i store
// npm install @reduxjs/toolkit react-redux

// ─── Slice — stan + akcje + reducery w jednym miejscu ────
// src/store/authSlice.js
import { createSlice } from "@reduxjs/toolkit";

const authSlice = createSlice({
  name: "auth",
  initialState: {
    user: null,
    isLoggedIn: false,
    isLoading: false
  },
  reducers: {
    // RTK używa Immer — możesz "mutować" state bezpiecznie!
    loginStart: (state) => { state.isLoading = true; },
    loginSuccess: (state, action) => {
      state.user = action.payload;
      state.isLoggedIn = true;
      state.isLoading = false;
    },
    logout: (state) => {
      state.user = null;
      state.isLoggedIn = false;
    }
  }
});

export const { loginStart, loginSuccess, logout } = authSlice.actions;
export default authSlice.reducer;

// ─── Store — łączy wszystkie slice'y ─────────────────────
// src/store/index.js
import { configureStore } from "@reduxjs/toolkit";
const store = configureStore({
  reducer: {
    auth: authReducer,
    cart: cartReducer,
    ui: uiReducer
  }
});
export default store;
Użycie Redux w komponentach + async thunks
// ─── Provider — owinięcie aplikacji ──────────────────────
import { Provider } from "react-redux";
<Provider store={store}><App /></Provider>

// ─── W komponentach ───────────────────────────────────────
import { useSelector, useDispatch } from "react-redux";
import { logout } from "./authSlice";

function Header() {
  const user = useSelector(state => state.auth.user);
  const dispatch = useDispatch();

  return (
    <header>
      <span>{user?.name}</span>
      <button onClick={() => dispatch(logout())}>Wyloguj</button>
    </header>
  );
}

// ─── Async Thunk — operacje asynchroniczne ────────────────
import { createAsyncThunk } from "@reduxjs/toolkit";

export const loginUser = createAsyncThunk(
  "auth/loginUser",
  async ({ email, password }, { rejectWithValue }) => {
    try {
      const { data } = await api.post("/auth/login", { email, password });
      return data.user;
    } catch (err) {
      return rejectWithValue(err.response?.data?.message);
    }
  }
);
// RTK automatycznie tworzy: loginUser.pending, .fulfilled, .rejected
// Obsługa w slice przez extraReducers: builder.addCase(loginUser.fulfilled, ...)
🤔 Kiedy Redux, kiedy Zustand? Redux/RTK — gdy projekt jest duży (wiele osób, wiele modułów), potrzebujesz Redux DevTools z time-travel debuggingiem, lub projektujesz serializowalną historię akcji. Zustand — gdy chcesz prostszego kodu, mniej boilerplate, i Redux DevTools nadal działa. W 2024 większość nowych projektów wybiera Zustand lub Jotai + React Query zamiast Redux. Redux nadal dominuje w istniejących dużych projektach.
📊 Redux vs Zustand — porównanie API
Aspekt Redux Toolkit Zustand
Setup configureStore + createSlice + Provider create() — jedno wywołanie, brak Providera
Odczyt stanu useSelector(state => state.auth.user) useStore(state => state.user)
Zapis stanu dispatch(action()) set() bezpośrednio
Async createAsyncThunk + extraReducers Normalny async/await w store
DevTools Redux DevTools (wbudowany) Redux DevTools (przez plugin)
Bundle size ~13kB (RTK) ~1kB

Dokumentacja Komponentów
Storybook — buduj i dokumentuj komponenty w izolacji
Storybook to narzędzie deweloperskie które uruchamia osobne środowisko (inny port, inny proces) gdzie możesz budować i testować komponenty UI niezależnie od reszty aplikacji. Każda "story" to jeden stan komponentu. To standard w większych firmach i design systemach.
Storybook — instalacja i pierwsza story
// Instalacja w istniejącym projekcie React/Vite:
// npx storybook@latest init
// → konfiguruje .storybook/main.js i .storybook/preview.js
// → tworzy przykładowe stories
// → npm run storybook → http://localhost:6006

// ─── Story — opis jednego stanu komponentu ────────────────
// src/components/Button/Button.stories.jsx
import { Button } from "./Button";

// Meta — konfiguracja dla całego pliku
export default {
  title: "Components/Button",     // ścieżka w sidebaru
  component: Button,
  tags: ["autodocs"],             // automatyczna dokumentacja
  argTypes: {
    variant: {
      control: "select",           // dropdown w Storybook UI
      options: ["primary", "secondary", "danger"]
    }
  }
};

// Każdy export = jedna story
export const Primary = {
  args: { variant: "primary", children: "Kliknij mnie" }
};

export const Danger = {
  args: { variant: "danger", children: "Usuń", disabled: false }
};

export const Loading = {
  args: { variant: "primary", children: "Zapisuję...", isLoading: true }
};
Storybook — play functions i testy wizualne
// ─── Play function — automatyczne interakcje w story ─────
import { within, userEvent, expect } from "@storybook/test";

export const FilledForm = {
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);

    // Symulacja: wpisz email i wyślij formularz
    await userEvent.type(
      canvas.getByLabelText("Email"),
      "user@example.com"
    );
    await userEvent.click(canvas.getByRole("button"));

    // Sprawdź czy pojawił się komunikat sukcesu
    await expect(
      canvas.getByText("Zapisano!")
    ).toBeInTheDocument();
  }
};

⚛️
Nie musisz wiedzieć wszystkiego od razu. Na początku skup się na: Tailwind (stylowanie), Axios (HTTP), React Router (nawigacja) i jednej bibliotece UI — shadcn/ui lub Ant Design. React Query i Redux/Zustand przyjdą naturalnie gdy poczujesz ból zarządzania stanem ręcznie. Storybook — gdy zaczniesz pracować w zespole z designerem lub budujesz komponent-library. Ikony — zainstaluj, importuj, używaj. Ekosystem React jest duży, ale każda biblioteka rozwiązuje jeden konkretny problem i ma świetną dokumentację.
