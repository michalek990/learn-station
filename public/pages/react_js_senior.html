JavaScript — Fundament
Typy, wartości i jak JavaScript naprawdę działa
JavaScript ma 8 typów danych, dynamiczne typowanie i kilka pułapek których nie widać na kursach dla początkujących. Zrozumienie jak działa silnik JS (event loop, call stack, heap) jest kluczowe dla każdego seniora.
Typy danych — pułapki i niespodzianki
// ─── 8 typów w JS ────────────────────────────────────────
// Primitive: string, number, bigint, boolean, undefined, null, symbol
// Reference: object (w tym Array, Function, Date...)

// ─── typeof — zaskakujące wyniki ─────────────────────────
typeof null        // ❌ "object" — historyczny bug w JS!
typeof []          // "object" — nie "array"
typeof function(){} // "function" (specjalny przypadek)
typeof undefined   // "undefined"
typeof 42n         // "bigint"

// ✅ Sprawdzanie null:
value === null
// ✅ Sprawdzanie Array:
Array.isArray(value)

// ─── Porównania == vs === ─────────────────────────────────
0 == ""      // true  ← type coercion (unikaj!)
0 === ""     // false ← strict equality
null == undefined  // true  ← jedyny wyjątek gdzie == ma sens
null === undefined // false
NaN === NaN        // false — NaN nie równa się sobie!
Number.isNaN(NaN)  // true  ← prawidłowe sprawdzenie

// ─── Falsy values — wszystkie 7 ──────────────────────────
// false, 0, -0, 0n, "", null, undefined, NaN
// Uwaga: [] i {} są TRUTHY!
Event Loop — jak JS jest jednowątkowy ale asynchroniczny
// ─── Call Stack / Heap / Event Loop ──────────────────────
// Call Stack — aktualnie wykonywane funkcje (LIFO)
// Heap      — alokacja pamięci dla obiektów
// Web APIs  — setTimeout, fetch, DOM events (poza V8)
// Callback Queue — oczekujące callbacki (macrotasks)
// Microtask Queue — Promise .then(), queueMicrotask()

// ─── Kolejność wykonywania ────────────────────────────────
console.log("1");                          // sync

setTimeout(() => console.log("2"), 0);    // macrotask

Promise.resolve()
  .then(() => console.log("3"));           // microtask

queueMicrotask(() => console.log("4"));  // microtask

console.log("5");                          // sync

// Output: 1, 5, 3, 4, 2
// Dlaczego? Sync → Microtasks → Macrotasks
// Microtask queue jest opróżniana w CAŁOŚCI
// przed każdym macrotask (np. setTimeout)

// ─── Praktyczne implikacje ───────────────────────────────
// ✅ await w async fn → zawiesza tylko tę funkcję
// ✅ long sync code blokuje UI (main thread)
// ✅ Web Workers → prawdziwa wielowątkowość
🔢 Number — pułapki

0.1 + 0.2 ≠ 0.3 — IEEE 754 float. Używaj toFixed() lub dedykowanej biblioteki do finansów.

Number.MAX_SAFE_INTEGER = 2^53-1. Przekroczenie: użyj BigInt.

Number.isInteger(n) vs n % 1 === 0 — pierwsze bezpieczniejsze.

parseInt("08") → zawsze podawaj radix: parseInt("08", 10).

// Primitives — kopiowane przez wartość
let a = 5;
let b = a;
b = 10;
// a nadal 5

// Objects — kopiowane przez referencję
const obj1 = { x: 1 };
const obj2 = obj1;
obj2.x = 99;
// obj1.x === 99 !

// ✅ Shallow copy
const copy = { ...obj1 };
// ✅ Deep copy (nowoczesny)
const deep = structuredClone(obj1);
⚡ Coercion — kiedy JS zmienia typy

"5" + 1 = "51" — konkatenacja, nie dodawanie

"5" - 1 = 4 — odejmowanie, coercion do number

+[] = 0, +{} = NaN

[] + [] = "", [] + {} = "[object Object]"

Reguła: używaj zawsze === i jawnej konwersji typów.

JavaScript — Scope, Closure & Hoisting
Leksykalny zakres, domknięcia i podnoszenie deklaracji
Closure to jeden z najważniejszych konceptów JS. Bez jego zrozumienia nie zrozumiesz jak działają moduły, hooks w Reakcie, ani wzorce takie jak memoization czy factory functions. Hoisting to kolejna pułapka dla nieświadomych.
Scope — var / let / const
// ─── var: function-scoped + hoisting ─────────────────────
function example() {
  if (true) {
    var x = 10;  // dostępna W CAŁEJ funkcji!
  }
  console.log(x); // 10 — mimo że poza if-blokiem
}

// ─── let/const: block-scoped ──────────────────────────────
function example2() {
  if (true) {
    let y = 10;
  }
  console.log(y); // ❌ ReferenceError — poza blokiem
}

// ─── Hoisting — deklaracje przenoszone na górę ────────────
console.log(a); // undefined (var hoisted, nie wartość)
var a = 5;

console.log(b); // ❌ ReferenceError — Temporal Dead Zone!
let b = 5;

// ─── Function declaration vs expression ──────────────────
foo();         // ✅ działa! Function declaration jest hoisted
function foo() {}

bar();         // ❌ TypeError: bar is not a function
var bar = function() {}; // expression — nie hoisted
Closure — praktyczne przykłady
// ─── Czym jest closure? ───────────────────────────────────
// Funkcja która "pamięta" swój leksykalny zakres
// nawet gdy jest wykonywana poza nim

function makeCounter() {
  let count = 0;           // zmienna w zewnętrznym scope
  return {
    increment: () => ++count,
    decrement: () => --count,
    value: () => count
  };
}

const counter = makeCounter();
counter.increment(); // 1
counter.increment(); // 2
counter.value();     // 2 — count żyje w closure

// ─── Klasyczna pułapka z var w pętli ─────────────────────
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Wynik: 3, 3, 3 — wszystkie closures dzielą TEN SAM i!

// ✅ Naprawione przez let (block scope):
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Wynik: 0, 1, 2 ✅

// ─── Closure w Reakcie (useCallback/useMemo) ─────────────
// Każdy render tworzy nową closure dla handlerów!
// Dlatego useCallback "zapamiętuje" closure ze starego renderu
💡 Closure w praktyce Closure to fundament wielu wzorców JS: moduły (IIFE), fabryki funkcji, memoization, partial application, currying, a w Reakcie — każdy hook opiera się na closure. Zrozumienie TDZ (Temporal Dead Zone) dla let/const pozwala unikać trudnych do debugowania bugów.

JavaScript — this, Prototype & Class
Kontekst wykonania, łańcuch prototypów i nowoczesne klasy
Słowo kluczowe this to jedno z najbardziej mylących pojęć w JS — jego wartość zależy od sposobu wywołania funkcji, nie od miejsca jej definicji. Łańcuch prototypów to podstawa dziedziczenia w JS.
this — 4 reguły wiązania
// ─── 1. Default binding — "use strict" vs normalny ───────
function whoAmI() { return this; }
whoAmI(); // window (browser) / global (Node) / undefined (strict)

// ─── 2. Implicit binding — obiekt przed kropką ────────────
const obj = {
  name: "React",
  greet() { return this.name; }
};
obj.greet(); // "React" ✅ — this = obj

const fn = obj.greet;
fn();        // undefined ❌ — this utracone po przypisaniu!

// ─── 3. Explicit binding — call / apply / bind ────────────
fn.call(obj);         // "React" ✅
fn.apply(obj);        // "React" ✅
const bound = fn.bind(obj);
bound();              // "React" ✅ — permanently bound

// ─── 4. new binding ───────────────────────────────────────
function Person(name) {
  this.name = name;  // this = nowo tworzony obiekt
}
const p = new Person("Anna");

// ─── Arrow functions — BRAK własnego this! ───────────────
const obj2 = {
  name: "React",
  greet: () => this.name   // ❌ this = enclosing scope (window!)
};
// ✅ Arrow functions dziedziczą this z miejsca definicji
// Idealne do callbacków: setTimeout(() => this.doSth())
Prototype Chain & Class syntax
// ─── Łańcuch prototypów ───────────────────────────────────
const animal = { breathes: true };
const dog = Object.create(animal);
dog.barks = true;

dog.breathes; // true — znalezione w prototype chain!
dog.hasOwnProperty("breathes"); // false — nie własne
dog.hasOwnProperty("barks");    // true

// ─── Class (ES6) — syntactic sugar nad prototype ─────────
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} makes a noise`;
  }
  static create(name) { return new Animal(name); }
}

class Dog extends Animal {
  speak() {
    return super.speak() + " — Woof!";
  }
}

// ─── Private fields (ES2022) ──────────────────────────────
class Counter {
  #count = 0;            // naprawdę prywatne (# prefix)
  increment() { this.#count++; }
  get value() { return this.#count; }
}
// counter.#count → SyntaxError z zewnątrz

ECMAScript 6+ — Nowy Standard
Destructuring, spread, modules, iterators i nowości ESNext
ES6 zmienił JavaScript na zawsze. Każdy React developer musi biegle posługiwać się destructuringiem, spread operatorem, template literals, optional chaining i nullish coalescing. Te cechy to chleb powszedni każdego projektu.
Destructuring — obiekty i tablice
// ─── Destructuring obiektów ───────────────────────────────
const user = { name: "Anna", age: 28, city: "Warsaw" };

const { name, age } = user;            // podstawowe
const { name: userName } = user;       // zmiana nazwy
const { role = "user" } = user;       // wartość domyślna
const { name, ...rest } = user;        // rest: {age, city}

// ─── Destructuring tablic ────────────────────────────────
const [first, second, ...others] = [1, 2, 3, 4];
const [, , third] = [1, 2, 3];       // pomijanie elementów

// ─── Zagnieżdżony destructuring ──────────────────────────
const { address: { street, city: userCity } } = {
  address: { street: "Main St", city: "Warsaw" }
};

// ─── W parametrach funkcji ───────────────────────────────
function greet({ name, age = 0 }) {
  return `${name}, lat: ${age}`;
}

// ─── Swap variables ───────────────────────────────────────
let a = 1, b = 2;
[a, b] = [b, a];  // ✅ swap bez temp variable
Optional chaining, Nullish coalescing, Logical operators
// ─── Optional chaining ?. (ES2020) ───────────────────────
const user = { profile: { avatar: null } };

user.profile?.avatar?.url    // undefined (nie TypeError!)
user.settings?.theme         // undefined
user.getAge?.()              // undefined (metoda opcjonalna)
arr?.[0]?.name               // bezpieczny dostęp do array

// ─── Nullish coalescing ?? (ES2020) ──────────────────────
const count = data.count ?? 0;    // 0 jeśli null/undefined
// Vs. || (OR) który też reaguje na falsy: 0, "", false
const n = 0 || 42;               // 42 — 0 jest falsy!
const m = 0 ?? 42;               // 0  — ?? sprawdza null/undef

// ─── Nullish assignment ??= (ES2021) ─────────────────────
user.role ??= "guest";  // przypisz tylko jeśli null/undefined
user.score ||= 0;       // przypisz jeśli falsy
user.count &&= user.count + 1; // przypisz jeśli truthy

// ─── Spread operator ─────────────────────────────────────
const merged = { ...defaults, ...overrides };  // merge
const copy = [...original];                    // shallow copy
const args = [1, 2, 3];
Math.max(...args);                             // 3

// ─── Modules (ES6) ───────────────────────────────────────
export const PI = 3.14;          // named export
export default function main() {} // default export
import { PI } from "./math";
import * as math from "./math"; // namespace import

JavaScript — Asynchroniczność
Callbacks, Promises, async/await i obsługa błędów
Asynchroniczność to serce nowoczesnego JS. Ewolucja od callbacków (callback hell) przez Promises do async/await. Znajomość metod Promise.all, allSettled, race, any jest obowiązkowa.
Promises — stany i łańcuchowanie
// ─── Promise — 3 stany ───────────────────────────────────
// pending → fulfilled | rejected

const p = new Promise((resolve, reject) => {
  setTimeout(() => {
    if (ok) resolve(data);
    else reject(new Error("Failed"));
  }, 1000);
});

// ─── .then() / .catch() / .finally() ────────────────────
p.then(data => process(data))
 .catch(err => console.error(err))
 .finally(() => setLoading(false));

// ─── Promise kombinatory ─────────────────────────────────

// Promise.all — czeka na WSZYSTKIE, fail-fast przy błędzie
const [users, posts] = await Promise.all([
  fetchUsers(), fetchPosts()
]);

// Promise.allSettled — czeka na WSZYSTKIE, nawet jeśli błąd
const results = await Promise.allSettled([p1, p2, p3]);
results.forEach(r => {
  if (r.status === "fulfilled") use(r.value);
  else log(r.reason);
});

// Promise.race — pierwszy który się rozstrzygnie
const result = await Promise.race([fetch1, timeout5s]);

// Promise.any — pierwszy SPEŁNIONY (ignoruje rejection)
const fastest = await Promise.any([mirror1, mirror2, mirror3]);
async/await — wzorce i pułapki
// ─── Podstawowy wzorzec ──────────────────────────────────
async function fetchUser(id) {
  try {
    const response = await fetch(`/api/users/${id}`);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } catch (err) {
    console.error("Fetch failed:", err);
    throw err; // re-throw lub obsłuż
  }
}

// ─── PUŁAPKA: await w pętli sekwencyjny! ────────────────
// ❌ Wolny — czeka na każdy request po kolei:
for (const id of ids) {
  const user = await fetchUser(id);
}

// ✅ Szybki — wszystkie requesty równolegle:
const users = await Promise.all(ids.map(fetchUser));

// ─── AbortController — anulowanie żądań ─────────────────
const controller = new AbortController();
const signal = controller.signal;

fetch("/api/data", { signal })
  .then(r => r.json())
  .catch(err => {
    if (err.name === "AbortError") return;
    throw err;
  });

controller.abort(); // np. przy unmount komponentu React

// ─── async/await zawsze zwraca Promise ───────────────────
async function getValue() { return 42; }
getValue(); // Promise<42> — nie 42!

⚛️
Props vs State — props to dane przekazane z góry (read-only, jednokierunkowy przepływ danych), state to wewnętrzny stan komponentu (mutable przez setState/hooks). Lifting state up — gdy dwa komponenty potrzebują tego samego stanu, przenieś go do wspólnego rodzica. Derived state — nie duplikuj danych z propsów do stanu; obliczaj je bezpośrednio lub przez useMemo.

React — Hooks Internals
useState, useEffect, useRef, useCallback, useMemo — jak naprawdę działają
Hooks to nie magia — to tablice (linked lists) w wewnętrznej strukturze React. Dlatego reguły hooków (tylko na najwyższym poziomie, tylko w funkcjach React) są absolutne — naruszenie ich psuje indeksowanie. Zrozumienie internals eliminuje 80% bugów z hookami.
useState — pułapki i wzorce
// ─── setState jest asynchroniczne! ───────────────────────
const [count, setCount] = useState(0);

setCount(count + 1);
setCount(count + 1);
setCount(count + 1);
// Wynik: count = 1, nie 3! Wszystkie używają stale `count`

// ✅ Functional update — używaj kiedy nowy stan zależy od starego:
setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1);
// Wynik: count = 3 ✅

// ─── Lazy initialization ─────────────────────────────────
// ❌ expensiveCalc() wywołana przy KAŻDYM renderze:
const [state, setState] = useState(expensiveCalc());

// ✅ Wywołana tylko raz przy inicjalizacji:
const [state, setState] = useState(() => expensiveCalc());

// ─── Update obiektów w stanie ────────────────────────────
// ❌ Mutacja — React nie zauważy zmiany:
state.user.name = "New Name";
setState(state);

// ✅ Nowy obiekt — immutable update:
setState(prev => ({
  ...prev,
  user: { ...prev.user, name: "New Name" }
}));
useEffect — dependency array i cleanup
// ─── 3 formy useEffect ───────────────────────────────────

// Bez deps — po każdym renderze:
useEffect(() => { doSomething(); });

// Pusta tablica [] — tylko po mount/unmount:
useEffect(() => { fetchData(); }, []);

// Z deps — gdy zmieni się wartość:
useEffect(() => { fetchUser(userId); }, [userId]);

// ─── Cleanup function ────────────────────────────────────
useEffect(() => {
  const subscription = api.subscribe(userId, handler);
  const timer = setInterval(tick, 1000);

  return () => {          // cleanup!
    subscription.unsubscribe();
    clearInterval(timer);
  };
}, [userId]);

// ─── Fetch z AbortController ─────────────────────────────
useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/users/${id}`, { signal: controller.signal })
    .then(r => r.json())
    .then(setUser)
    .catch(err => {
      if (err.name !== "AbortError") setError(err);
    });
  return () => controller.abort(); // ✅ anuluj przy cleanup
}, [id]);

// ─── Częste błędy z dependency array ────────────────────
// Missing dep → stale closure (stare wartości)
// Extra dep → zbyt częste re-running
// Funkcje w deps → useCallback
// Obiekty w deps → useMemo lub prymitywne wartości
🗄️ useRef
// Dwa zastosowania useRef:

// 1. Referencja do DOM node
const inputRef = useRef(null);
<input ref={inputRef} />
inputRef.current.focus();

// 2. "Instance variable"
// — mutable, NIE powoduje re-render!
const timerRef = useRef(null);
timerRef.current = setInterval(fn, 1000);

// Poprzednia wartość props/state:
function usePrevious(value) {
  const ref = useRef();
  useEffect(() => {
    ref.current = value;
  });
  return ref.current;
}

React — Custom Hooks
Tworzenie własnych hooków — wzorce i przykłady
Custom hooks to podstawowy mechanizm reużycia logiki stanowej w React. Każda funkcja zaczynająca się od use która wywołuje inne hooki to custom hook. Dobre custom hooks mają pojedynczą odpowiedzialność i jasne API.
Custom Hooks — przykłady użytkowe
// ─── useFetch — dane z API ────────────────────────────────
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);

    fetch(url, { signal: controller.signal })
      .then(r => r.json())
      .then(setData)
      .catch(err => {
        if (err.name !== "AbortError") setError(err);
      })
      .finally(() => setLoading(false));

    return () => controller.abort();
  }, [url]);

  return { data, loading, error };
}

// ─── useLocalStorage ─────────────────────────────────────
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const item = localStorage.getItem(key);
      return item ? JSON.parse(item) : initialValue;
    } catch { return initialValue; }
  });

  const set = useCallback(newValue => {
    setValue(newValue);
    localStorage.setItem(key, JSON.stringify(newValue));
  }, [key]);

  return [value, set];
}
Więcej wzorców custom hooks
// ─── useDebounce ─────────────────────────────────────────
function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);
  return debounced;
}

// Użycie:
const [query, setQuery] = useState("");
const debouncedQuery = useDebounce(query, 500);
useEffect(() => search(debouncedQuery), [debouncedQuery]);

// ─── useToggle ────────────────────────────────────────────
function useToggle(initial = false) {
  const [value, setValue] = useState(initial);
  const toggle = useCallback(() => setValue(v => !v), []);
  return [value, toggle];
}

// ─── useEventListener ────────────────────────────────────
function useEventListener(event, handler, element = window) {
  const savedHandler = useRef(handler);
  useEffect(() => { savedHandler.current = handler; });
  useEffect(() => {
    const listener = e => savedHandler.current(e);
    element.addEventListener(event, listener);
    return () => element.removeEventListener(event, listener);
  }, [event, element]);
}

// ─── useMediaQuery ────────────────────────────────────────
function useMediaQuery(query) {
  const [matches, setMatches] = useState(
    () => window.matchMedia(query).matches
  );
  useEffect(() => {
    const media = window.matchMedia(query);
    const handler = e => setMatches(e.matches);
    media.addEventListener("change", handler);
    return () => media.removeEventListener("change", handler);
  }, [query]);
  return matches;
}

React — Optymalizacja Wydajności
React.memo, useCallback, useMemo — kiedy używać, kiedy nie
Przedwczesna optymalizacja to wróg. Ale gdy profiler pokazuje problem, musisz wiedzieć jak go rozwiązać. React.memo, useCallback, useMemo mają koszt — używaj tylko gdy jest zmierzony problem.
React.memo, useCallback, useMemo
// ─── React.memo — pomija re-render gdy props się nie zmieniły
const ExpensiveList = React.memo(function List({ items, onSelect }) {
  console.log("Render List");  // tylko gdy items/onSelect zmieni się
  return items.map(item => ...);
});

// ─── PUŁAPKA: Funkcja tworzona przy każdym renderze! ─────
function Parent() {
  const handleSelect = (id) => doSomething(id);
  // ❌ Nowa referencja przy każdym renderze Parent!
  // React.memo na List i tak re-renderuje bo onSelect !== onSelect
  return <ExpensiveList onSelect={handleSelect} />;
}

// ✅ useCallback — memoizuje funkcję:
const handleSelect = useCallback((id) => {
  doSomething(id);
}, []);  // pusta tablica = ta sama funkcja zawsze

// ─── useMemo — memoizuje wynik obliczeń ──────────────────
// ❌ Oblicza przy każdym renderze:
const total = cart.reduce((sum, item) => sum + item.price, 0);

// ✅ Przelicza tylko gdy cart się zmieni:
const total = useMemo(
  () => cart.reduce((sum, item) => sum + item.price, 0),
  [cart]
);

React — Wzorce Projektowe
Compound Components, Render Props, HOC i nowoczesne alternatywy
Wzorce projektowe w React ewoluowały przez lata. HOC i Render Props były dominujące przed hookami — teraz custom hooks zastąpiły większość ich zastosowań. Compound Components nadal są aktualne dla bibliotek komponentów.
Compound Components — elastyczne API
// Wzorzec: Select z sub-komponentami (jak HTML <select><option>)
const SelectCtx = createContext();

function Select({ children, onChange }) {
  const [selected, setSelected] = useState(null);
  const select = useCallback(value => {
    setSelected(value);
    onChange?.(value);
  }, [onChange]);

  return (
    <SelectCtx.Provider value={{ selected, select }}>
      <div className="select">{children}</div>
    </SelectCtx.Provider>
  );
}

function Option({ value, children }) {
  const { selected, select } = useContext(SelectCtx);
  return (
    <div
      className={selected === value ? "active" : ""}
      onClick={() => select(value)}
    >{children}</div>
  );
}

Select.Option = Option;  // namespace

// Użycie — elastyczne, nie musisz znać internals:
<Select onChange={setTheme}>
  <Select.Option value="light">Light</Select.Option>
  <Select.Option value="dark">Dark</Select.Option>
</Select>

// ─── Error Boundary — łapie błędy renderowania ───────────
// Tylko class component! (lub react-error-boundary library)
class ErrorBoundary extends Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }
  componentDidCatch(error, info) {
    logToSentry(error, info.componentStack);
  }
  render() {
    if (this.state.hasError)
      return <ErrorFallback error={this.state.error} />;
    return this.props.children;
  }
}

// ✅ react-error-boundary — prostsze, z hooks:

  onError={(err) => logError(err)}>
  <MyFeature />
</ErrorBoundary>
