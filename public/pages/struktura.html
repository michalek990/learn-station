▶
Gwarancja że wszyscy w zespole mają te same wersje bibliotek. Yarn generuje go automatycznie. Nie edytujesz ręcznie — tylko commituj do gita.

  version "18.2.0"         ← dokładna wersja
  resolved "https://registry..."
  integrity sha512-...    ← checksum bezpieczeństwa

⚙️ TypeScript
JSONtsconfig.json
Konfiguracja TypeScript + aliasy @/
▶
Mówi TypeScriptowi jak sprawdzać kod. Najważniejsze: strict: true (surowy tryb) i paths (aliasy @/ żeby TS rozumiał importy).
tsconfig.json
"strict": true,           // surowy tryb
"noUnusedLocals": true,   // błąd za nieużywane zmienne
"paths": {
  "@/features/*": ["src/app/features/*"],
  "@/shared/*":   ["src/app/shared/*"],
  "@/layouts/*":  ["src/app/layouts/*"]
  // aliasy @ — skróty do folderów
}

⚡ Vite & Vitest
TSvite.config.ts
Build, devserver i aliasy @/
▶
Konfiguracja Vite — narzędzia które buduje projekt. Najważniejsze: aliasy @/ (skróty do folderów) i pluginy. Aliasy MUSZĄ być tu i w tsconfig.
vite.config.ts
defineConfig({
  plugins: [react(), eslint()],
  resolve: {
    alias: [
      { find: '@/shared', replacement: '/src/app/shared' },
      { find: '@/features', replacement: '/src/app/features' },
      // bez aliasów: '../../../shared/utils'
      // z aliasami:  '@/shared/utils' ✅
    ]
  }
})
TSvitest.config.ts
Konfiguracja testów (dziedziczy z Vite)
▶
Ustawienia dla testów automatycznych. Dziedziczy konfigurację Vite więc aliasy @/ działają też w testach. jsdom symuluje przeglądarkę w Node.js.

🐕 Husky — Git Hooks
SHpre-commit
Odpala się PRZED każdym commitem
▶
Blokuje commit jeśli testy nie przechodzą. Nie możesz wrzucić zepsutego kodu do repozytorium.
.husky/pre-commit
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

yarn run test   # testy muszą przejść!
# fail → commit zablokowany ❌
SHcommit-msg
Sprawdza format wiadomości commita
▶
Wymusza Conventional Commits. Wiadomości muszą mieć określony format — nie możesz napisać "poprawki" albo "fix".
Przykłady commitów
✅ feat: dodanie strony logowania
✅ fix: naprawienie błędu w tabeli
✅ chore: aktualizacja zależności
✅ refactor: przepisanie serwisu

❌ "poprawki"
❌ "fix"
❌ "WIP"
❌ "asdasd"
📋 Issue Templates
MDbug_report.md
Szablon zgłaszania błędów na GitHubie
▶
Gdy ktoś klika "New Issue" na GitHubie, zamiast pustego pola dostaje gotowy formularz. Wymusza podanie kroków reprodukcji, przeglądarki, systemu. Automatycznie dodaje labelki: bug, need analysis.
bug_report.md (struktura)
**Describe the bug**      ← co się psuje
**To Reproduce**          ← kroki do odtworzenia
**Expected behavior**     ← co powinno działać
**Screenshots**           ← opcjonalne
**Browser / OS**          ← środowisko

// Bez szablonu: "nie działa" 🙄
// Z szablonem: developer ma wszystko ✅
MDfeature_request.md
Szablon prośby o nową funkcjonalność
▶
Ustrukturyzowana prośba o nową funkcję. Pyta o problem który rozwiązuje, jak powinna działać i jakie alternatywy rozważano. Labelki: enhancement, need analysis.
feature_request.md (struktura)
**Problem?**              ← po co ta funkcja
**Rozwiązanie**           ← jak ma działać
**Alternatywy**           ← co jeszcze rozważałeś
⚡ Jak działa Husky przy commicie git commit -m "feat: nowa strona" → pre-commit: yarn test (testy OK?) → commit-msg: commitlint (dobry format?) → commit zapisany ✅. Każdy fail = commit zablokowany.

TSauth.context.ts
Tworzy kontekst + hook useAuth()
▶
Gniazdko elektryczne — samo w sobie nic nie robi, tylko definiuje interfejs dostępu. Hook useAuth() to sposób na odczyt danych z dowolnego komponentu.

export const AuthContext = 
  createContext<AuthContextType | null>(null)

// hook — odczyt stanu z każdego komponentu
export const useAuth = () => {
  const ctx = useContext(AuthContext)
  if (!ctx) throw new Error('Brak AuthProvider!')
  return ctx
}

🎨 theme-provider
TSXtheme.provider.tsx
Ciemny / jasny motyw aplikacji
▶
Zarządza motywem light/dark. Dodaje klasę dark do elementu HTML co aktywuje ciemny motyw Tailwinda. Zapisuje preferencję w localStorage.
theme.provider.tsx
const ThemeProvider = ({ children }) => {
  const [theme, setTheme] = useState('light')

  useEffect(() => {
    // dodaj/usuń klasę 'dark' z <html>
    document.documentElement.classList
      .toggle('dark', theme === 'dark')
  }, [theme])

  return <ThemeContext.Provider value={{ theme, setTheme }}>
    {children}
  </ThemeContext.Provider>
}

⚡ http-client (shared/utils)
TShttp.ts
Instancja Axiosa z interceptorami
▶
Serce komunikacji z API. Tworzy skonfigurowanego klienta HTTP. Interceptor request = auto-dodaje token do każdego zapytania. Interceptor response = obsługa błędów.
http.ts
const http = axios.create({
  baseURL: import.meta.env.VITE_API_URL
})

// przed każdym zapytaniem:
http.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config  // nie musisz dodawać tokenu ręcznie!
})
TSgetAuthToken.ts
Pobiera token z localStorage
▶
Czyta token z localStorage i zwraca w formacie Bearer xxx. Zwraca null jeśli użytkownik nie jest zalogowany.
getAuthToken.ts
export default () => {
  const token = localStorage.getItem('token')
  if (!token) return null
  return `Bearer ${token}`
}

Dwie kluczowe funkcje. cn() — łączy klasy Tailwinda bez konfliktów (najczęściej używana funkcja w projekcie). processSnapshot() — naprawia format danych z Firebase.
common.utils.ts
// cn() — łączy klasy Tailwinda
export const cn = (...inputs) => twMerge(clsx(inputs))

// problem bez cn:
'bg-red-500 bg-blue-500'  ← która wygra? losowo!
// cn rozwiązuje: wygrywa ostatnia ✅

// processSnapshot() — naprawia Firebase
// Firebase: { data: {...}, id: 'abc' }  ← id osobno
// po processSnapshot: { ...data, id }  ← id w środku ✅

🎨 shadcn/ui — czym jest Nie instaluje paczki — kopiuje kod komponentu bezpośrednio do projektu (src/app/components/ui/button.tsx). Twój plik, twój kod, zmieniasz co chcesz. Radix UI dostarcza logikę i dostępność, Tailwind dodaje wygląd, shadcn łączy jedno z drugim.

Podsumowanie
Jak to wszystko działa razem
index.html → ładuje src/index.tsx → montuje App.tsx
App.tsx → owija w Providers (auth, theme) → przekazuje do routes.tsx
routes.tsx → URL /vehicles → wybiera TopNavigationLayout
Layout → renderuje Navbar + Sidebar + VehiclesPage
VehiclesContainer → fetuje z ItemService → przekazuje do komponentu
ItemService → używa http.ts → auto-dodaje token → zapytanie do API
Komponent → wyświetla dane używając shared/ui-base + shadcn/ui
🏛️ Zasada hierarchii shared/ używa każdy  ·  services/ używają pages i features  ·  pages/ używa tylko siebie. Nigdy odwrotnie — strona nie importuje z innej strony.
🚪 Wzorzec public-api Każdy moduł ma index.ts + public-api.ts. Importujesz zawsze z @/nazwa-modułu, nigdy bezpośrednio z pliku. Możesz zmienić wewnętrzną strukturę bez ruszania reszty apki.
🔒 Jakość kodu ESLint pilnuje poprawności → Prettier formatuje wygląd → Husky blokuje commit jeśli testy padają lub commit ma zły format → yarn.lock zapewnia te same wersje u każdego.
