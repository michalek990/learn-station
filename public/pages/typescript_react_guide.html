Fundamenty języka
Czym jest TypeScript — jak działa, co daje, czym nie jest
TypeScript to JavaScript z systemem typów. Kompiluje się do czystego JS — przeglądarka nigdy nie widzi kodu TS. Typy istnieją tylko w czasie kompilacji i całkowicie znikają w runtime. Każdy poprawny JS jest poprawnym TS.
TypeScript → JavaScript — co robi kompilator
// ══ CO PISZESZ W .ts / .tsx ═══════════════════
function greet(name: string): string {
  return `Cześć, ${name}!`;
}

interface User {
  id:    number;
  name:  string;
  email?: string;   // ? = opcjonalne
}

const user: User = { id: 1, name: "Jan" };

// ══ CO DOSTAJE PRZEGLĄDARKA (po tsc / Vite) ═══
// function greet(name) {
//   return `Cześć, ${name}!`;
// }
// const user = { id: 1, name: "Jan" };
//
// interface User — ZNIKA CAŁKOWICIE
// : string, : number — ZNIKAJĄ CAŁKOWICIE

// ══ SUPERSET — JS jest poprawnym TS ═══════════
const x = 5;          // TS inferuje: number
const y: number = 5;  // jawna adnotacja — to samo
// Inference > jawna adnotacja gdy typ jest oczywisty

// ══ BŁĘDY TYLKO W KOMPILACJI ══════════════════
function add(a: number, b: number) { return a + b; }

add("1", 2);  // ❌ błąd kompilacji: string ≠ number
// W runtime i tak by zadziałało — TS tylko ostrzega
// Kompilator TS NIE zatrzymuje działania aplikacji
📁 Pliki i narzędzia — co co robi
.ts
Czysty TypeScript — logika, serwisy, hooki, utility. Bez JSX. Próba użycia <div> tutaj = błąd.
.tsx
TypeScript + JSX. Komponenty React muszą być .tsx — nawet jeśli jedna linia używa JSX.
tsconfig.json
Konfiguracja kompilatora. strict: true włącza wszystkie rygorystyczne opcje — używaj zawsze.
tsc --noEmit
Sprawdza typy bez generowania plików JS. Używaj w CI do weryfikacji typów.
Vite / esbuild
Nie sprawdza typów! Tylko transpiluje TS→JS. Aplikacja uruchomi się mimo błędów typów.
@types/*
Paczki z typami dla bibliotek JS: @types/node. Instaluj jako devDependencies.
.d.ts
Plik deklaracji — same typy, zero logiki. Opisuje kształt bibliotek napisanych w JS.
Vite nie sprawdza typów — pułapka! W projekcie React z Vite możesz mieć błędy TypeScript i aplikacja nadal się uruchomi. Vite używa esbuild — szybki, ale ignoruje błędy typów. Dodaj tsc --noEmit do skryptów CI albo zainstaluj vite-plugin-checker żeby widzieć błędy podczas dev.

System Typów
Typy podstawowe — any, unknown, never, union, literal, tuple
TypeScript ma bogaty system typów. any wyłącza sprawdzanie — to rezygnacja z TS. unknown to bezpieczna alternatywa — zmusza do sprawdzenia przed użyciem. never to typ niemożliwy — używany do exhaustive checks i funkcji które nigdy nie wracają.
Prymitywy, arrays, tuples, union, literal
// ══ TYPY PRYMITYWNE ═══════════════════════════
let n:   number    = 42;
let s:   string    = "hello";
let b:   boolean   = true;
let u:   undefined = undefined;
let nl:  null      = null;
let big: bigint    = 9007199254740991n;

// ══ TABLICE ═══════════════════════════════════
const nums: number[]       = [1, 2, 3];
const strs: Array<string> = ["a", "b"]; // to samo

// ══ TUPLE — znana długość i kolejność typów ════
const pair:  [string, number]  = ["Jan", 30];
const [name, age] = pair;        // destructuring z typami

// Named tuple (TS 4.0)
type Range = [min: number, max: number];

// ══ UNION — jeden z kilku typów ═══════════════
let id: string | number;
id = "abc"; // ok
id = 123;   // ok
id = true;  // ❌ boolean nie pasuje

// ══ LITERAL TYPES — konkretna wartość jako typ ═
type Direction = "left" | "right" | "up" | "down";
type Status    = "active" | "inactive" | "pending";
type DiceRoll  = 1 | 2 | 3 | 4 | 5 | 6;

function move(dir: Direction) { /* ... */ }
move("left");      // ✅
move("diagonal");  // ❌ nie ma w union

// ══ INTERSECTION — oba naraz ══════════════════
type AdminUser = User & { permissions: string[] };
// obiekt musi spełniać OBA interfejsy jednocześnie
any vs unknown vs never vs void — kluczowe różnice
// ══ ANY — wyłącza type checking (unikaj!) ═════
let danger: any = "hello";
danger = 42;               // ok
danger.toUpperCase();      // ok (nawet jeśli number!)
danger.nieIstniejąca();  // ok — zero sprawdzania
// any "zaraża" — przekazanie do funkcji wyłącza check tam też

// ══ UNKNOWN — bezpieczny any ══════════════════
let safe: unknown = "hello";
safe.toUpperCase();        // ❌ BŁĄD — musisz sprawdzić typ!

if (typeof safe === "string") {
  safe.toUpperCase();      // ✅ po sprawdzeniu działa
}
// unknown = "coś dostałem ale nie wiem co"
// Używaj dla danych z API, catch(e: unknown), JSON.parse

// ══ NEVER — typ niemożliwy ════════════════════
// 1. Funkcja która nigdy nie wraca
function throwError(msg: string): never {
  throw new Error(msg); // nigdy nie dochodzi do return
}

// 2. Exhaustive check — TS pilnuje że obsłużysz wszystkie przypadki
type Shape = "circle" | "square" | "triangle";
function getArea(s: Shape): number {
  switch(s) {
    case "circle":   return 3.14;
    case "square":   return 1;
    case "triangle": return 0.5;
    default: const _check: never = s;
    // Gdy dodasz nowy Shape bez nowego case → błąd kompilacji!
  }
}

// ══ VOID — brak znaczącej wartości zwracanej ══
function log(msg: string): void { console.log(msg); }
// void ≠ undefined. void = "nie interesuje mnie wynik"
any = rezygnacja z TypeScript Każde any to dziura. Zamiast tego: unknown gdy nie znasz typu (dane z API, catch block), never gdy coś jest niemożliwe, konkretny typ gdy wiesz co to. Włącz "noImplicitAny": true w tsconfig — błąd gdy TS nie może wyinferować bez pomocy.

Struktury typów
interface vs type — różnice, kiedy co używać
Dwa sposoby opisywania kształtu obiektów. interface ma declaration merging i może być extends-owany — lepszy dla publicznych API i OOP. type jest elastyczniejszy — obsługuje union, mapped types, conditional types. W React używaj obu — ważna konsekwencja w projekcie.
interface — składnia, extends, declaration merging
// ══ PODSTAWOWY INTERFACE ══════════════════════
interface User {
  id:       number;
  name:     string;
  email?:   string;         // ? = opcjonalne pole
  readonly createdAt: Date; // readonly = nie można nadpisać
}

// ══ EXTENDS — dziedziczenie interface ══════════
interface Admin extends User {
  permissions: string[];
  level:       1 | 2 | 3;
}

// Wielokrotne extends
interface SuperAdmin extends Admin, Auditable {
  superKey: string;
}

// ══ DECLARATION MERGING — tylko interface ══════
// Można zdeklarować dwa razy — TS łączy je!
interface Window {
  myApp: { version: string };
}
// Teraz window.myApp jest znane TypeScriptowi
// Używane do augmentacji typów bibliotek np. Express.Request

// ══ INTERFACE DLA FUNKCJI ═════════════════════
interface Comparator<T> {
  (a: T, b: T): number;
}
const byAge: Comparator<User> = (a, b) => a.id - b.id;

// ══ INDEX SIGNATURE ═══════════════════════════
interface Dict<V> {
  [key: string]: V;  // dowolne klucze string → wartość V
}
const scores: Dict<number> = { jan: 95, anna: 88 };
type — alias, union, intersection, obiekty
// ══ TYPE ALIAS — może być czymkolwiek ═════════
type ID       = string | number;
type Status   = "active" | "inactive";
type Callback = (err: Error | null, data?: string) => void;
type Pair<T>  = [T, T];   // tuple z generykiem

// Obiektowy type — podobny do interface
type Point = {
  x: number;
  y: number;
};

// "Extends" przez intersection
type Point3D = Point & { z: number };

// ══ RÓŻNICE interface vs type ══════════════════
// interface: declaration merging ✅  type: ❌
// interface: extends              ✅  type: & intersection
// type: union types               ✅  interface: ❌
// type: conditional types         ✅  interface: ❌
// type: mapped types              ✅  interface: ❌
// type: tuple aliases             ✅  interface: ❌

// ══ DISCRIMINATED UNION — złoty wzorzec ════════
type ApiState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error";   error: string };

// Switch na status.status daje pełne narrowing
function render(state: ApiState<User>) {
  switch(state.status) {
    case "success": return state.data.name; // data: User ✅
    case "error":   return state.error;     // error: string ✅
    case "loading": return "Ładowanie...";
    case "idle":    return null;
  }
}
Kiedy interface, kiedy type? interface → obiekty, klasy, publiczne API biblioteki, gdy potrzebujesz declaration merging. type → union, tuple, funkcje, mapped/conditional types, gdy nie budujesz klasy. W React: oba działają dla Props — ważna konsekwencja w projekcie. Mieszanie to chaos.

Wbudowane transformacje typów
Utility Types — Partial, Pick, Omit, Record, keyof, typeof, as const
TypeScript ma wbudowane typy-narzędzia do transformowania innych typów. Zamiast pisać nowe interfejsy ręcznie, możesz wyprowadzać je ze starych. keyof i typeof to operatory poziome typów. as const zamraża wartości na literal types.
Partial, Required, Readonly, Pick, Omit, Record
interface User {
  id:    number;
  name:  string;
  email: string;
  age:   number;
}

// ══ PARTIAL — wszystkie pola opcjonalne ═══════
type UpdateUser = Partial<User>;
// { id?: number; name?: string; email?: string; age?: number }
// Używane np. dla PATCH requests — możesz wysłać tylko część

// ══ REQUIRED — wszystkie wymagane ════════════
type FullUser = Required<User>;

// ══ READONLY — pola tylko do odczytu ══════════
type FrozenUser = Readonly<User>;
const u: FrozenUser = { id: 1, name: "Jan", email: "", age: 30 };
u.name = "Anna";  // ❌ Cannot assign to 'name' — readonly

// ══ PICK — wybierz konkretne pola ════════════
type UserPreview = Pick<User, "id" | "name">;
// { id: number; name: string } — tylko te dwa pola

// ══ OMIT — usuń konkretne pola ═══════════════
type CreateUser = Omit<User, "id">;
// { name: string; email: string; age: number } — bez id

// ══ RECORD — mapa klucz→wartość ══════════════
type ScoreMap   = Record<string, number>;
type UserByRole = Record<"admin" | "user", User[]>;
// { admin: User[]; user: User[] } — klucze muszą istnieć

// ══ EXCLUDE / EXTRACT ════════════════════════
type T = "a" | "b" | "c";
type NoA     = Exclude<T, "a">;       // "b" | "c"
type OnlyAB  = Extract<T, "a" | "b">; // "a" | "b"
type NoNull  = NonNullable<string | null | undefined>; // string
keyof, typeof, as const, ReturnType, Awaited
// ══ KEYOF — klucze obiektu jako union ════════
type UserKey = keyof User; // "id" | "name" | "email" | "age"

// Bezpieczny getter — klucz musi istnieć w T
function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
get(user, "name");   // ➜ string ✅
get(user, "xyz");    // ➜ ❌ błąd — "xyz" nie jest kluczem User

// ══ TYPEOF — wyciągnij typ ze zmiennej ════════
const config = { host: "localhost", port: 3000 };
type Config = typeof config; // { host: string; port: number }

// ══ AS CONST — literal types z wartości ═══════
const ROLES = ["admin", "user", "coordinator"] as const;
// Bez as const: string[]  ← bezsensownie szeroki
// Z as const:   readonly ["admin", "user", "coordinator"]
type Role = typeof ROLES[number]; // "admin" | "user" | "coordinator"

const COLORS = { red: "#ff0000", blue: "#0000ff" } as const;
type Color = typeof COLORS[keyof typeof COLORS];
// "#ff0000" | "#0000ff"

// ══ RETURNTYPE / PARAMETERS ═══════════════════
function fetchUser(id: number) { return { id, name: "Jan" }; }

type UserResult = ReturnType<typeof fetchUser>;
// { id: number; name: string }
type FetchParams = Parameters<typeof fetchUser>;
// [id: number]

// ══ AWAITED — unwrap Promise ═══════════════════
async function getUser(): Promise<User> { /* ... */ }
type Resolved = Awaited<ReturnType<typeof getUser>>;
// User  ← unwrap Promise<User> → User

Generyki
Generic types — parametry typów, constrainty, infer
Generyki to typy-parametry — jak argumenty funkcji, ale dla typów. Pozwalają pisać reużywalny, w pełni typowany kod. Constrainty (extends) ograniczają co może być przekazane. infer pozwala wyciągać typy z innych typów.
Generyki — funkcje, interfejsy, constrainty
// ══ PODSTAWOWY GENERYK ════════════════════════
function identity<T>(value: T): T { return value; }

identity<string>("hello");  // jawny typ
identity(42);               // T inferowane jako number

// ══ GENERYCZNY INTERFEJS ══════════════════════
interface ApiResponse<T> {
  data:    T;
  status:  number;
  message: string;
}
type UserResp  = ApiResponse<User>;       // data: User
type UsersResp = ApiResponse<User[]>;     // data: User[]

// ══ CONSTRAINTY — T musi spełniać warunek ═════
// T musi mieć pole .length
function getLength<T extends { length: number }>(val: T): number {
  return val.length;
}
getLength("hello");    // 5 ✅ string ma length
getLength([1, 2, 3]);  // 3 ✅ array ma length
getLength(42);          // ❌ number nie ma length

// K musi być kluczem T
function pluck<T, K extends keyof T>(arr: T[], key: K): T[K][] {
  return arr.map(item => item[key]);
}
const names = pluck(users, "name"); // string[] ✅
pluck(users, "xyz");                // ❌ nie ma takiego klucza

// ══ WIELE PARAMETRÓW ══════════════════════════
function zip<A, B>(a: A[], b: B[]): [A, B][] {
  return a.map((v, i) => [v, b[i]]);
}
zip([1, 2], ["a", "b"]); // [number, string][]
Conditional types, infer, default type params
// ══ CONDITIONAL TYPE ══════════════════════════
type IsArray<T> = T extends any[] ? "array" : "not array";
type R1 = IsArray<string[]>;  // "array"
type R2 = IsArray<number>;    // "not array"

// ══ INFER — wyciągnij typ "w środku" ══════════
// Wyciągnij typ elementu tablicy
type Unwrap<T> = T extends (infer U)[] ? U : T;
type A = Unwrap<string[]>;  // string
type B = Unwrap<number>;    // number (nie jest array)

// Wyciągnij typ zwracany funkcji (jak ReturnType)
type Ret<T> = T extends (...args: any[]) => infer R ? R : never;

// ══ DEFAULT TYPE PARAMS ════════════════════════
interface State<T = unknown> {
  data: T;
  loading: boolean;
  error: string | null;
}
const s1: State          = { data: null, loading: false, error: null };
const s2: State<User>    = { data: user, loading: false, error: null };
const s3: State<User[]> = { data: [],   loading: true,  error: null };

// ══ TEMPLATE LITERAL TYPES (TS 4.1) ═══════════
type EventName<T extends string> = `on${Capitalize<T>}`;
type ClickEv = EventName<"click">;   // "onClick"
type CSSPx   = `${number}px`;          // "0px", "16px" itp
type ApiPath = `/api/${string}`;        // "/api/users" itd

Zwężanie typów
Narrowing — typeof, instanceof, in, type guards, satisfies
TypeScript analizuje kod i zwęża typy automatycznie po sprawdzeniach warunkowych. Type guards to funkcje które mówią kompilatorowi "jeśli zwraca true, wiem jaki to konkretny typ". satisfies (TS 4.9) sprawdza typ bez tracenia precyzji.
typeof, instanceof, in — wbudowane narrowing
// ══ TYPEOF NARROWING ══════════════════════════
function format(val: string | number | boolean) {
  if (typeof val === "string")  return val.toUpperCase(); // string
  if (typeof val === "number")  return val.toFixed(2);    // number
  return val ? "tak" : "nie";                             // boolean
}

// ══ INSTANCEOF NARROWING ══════════════════════
function handle(e: unknown) {
  if (e instanceof Error)     return e.message;    // Error ✅
  if (e instanceof TypeError) return e.message;    // TypeError ✅
  return String(e);
}

// ══ IN OPERATOR — sprawdź czy pole istnieje ════
interface Cat { meow(): void }
interface Dog { bark(): void; fetch(): void }

function speak(animal: Cat | Dog) {
  if ("meow" in animal) {
    animal.meow(); // TS wie: Cat ✅
  } else {
    animal.bark(); // TS wie: Dog ✅
  }
}

// ══ TRUTHINESS NARROWING ═════════════════════
function greet(name: string | null | undefined) {
  if (name) {
    return `Cześć, ${name}!`; // name: string (nie null/undefined)
  }
  return "Cześć, nieznajomy!";
}
// UWAGA: "" (pusty string) też jest falsy! Uważaj.
Custom type guards, as, satisfies, non-null assertion
// ══ CUSTOM TYPE GUARD — predykat typu ══════════
// Zwraca "value is Type" — TS ufa tej funkcji
function isUser(val: unknown): val is User {
  return (
    typeof val === "object" && val !== null &&
    "id" in val && "name" in val
  );
}

const data: unknown = JSON.parse(response);
if (isUser(data)) {
  data.name; // TS wie: User ✅ — bo type guard mówi prawdę
}

// ══ TYPE ASSERTION — as ═══════════════════════
// Mówisz TS: "wiem lepiej niż ty"
const inp = document.getElementById("email") as HTMLInputElement;
inp.value; // TS ufa — ale jeśli element nie istnieje = crash

// Double assertion — niebezpieczne!
const x = "hello" as unknown as number; // TS pozwoli, runtime może crashnąć

// ══ NON-NULL ASSERTION — ! ════════════════════
const name = user.name!; // "wiem że nie jest null/undefined"
// Używaj rzadko — lepsza opcja: optional chaining + if

// ══ SATISFIES (TS 4.9) — sprawdź bez utraty ══
const palette = {
  red:   [255, 0, 0],
  green: "#00ff00",
} satisfies Record<string, string | number[]>;

palette.red.map(Math.round);   // ✅ TS wie że red = number[]
palette.green.toUpperCase();  // ✅ TS wie że green = string
// "as" straciłoby tę informację — satisfies zachowuje
as vs satisfies — różnica kluczowa as Type mówi TS "traktuj to jako Type" i traci precyzję — TS zapomina o wewnętrznych typach. satisfies Type sprawdza czy pasuje do Type ale zachowuje precyzyjny typ. Używaj satisfies gdy chcesz walidować kształt bez tracenia szczegółów.

JSX & Pliki .tsx
Czym jest JSX — jak działa, różnice vs HTML, typy elementów
JSX to rozszerzenie składni JS które wygląda jak HTML, ale nim nie jest. Kompiluje się do wywołań React.createElement(). Plik .tsx = TypeScript + JSX. Każdy tag JSX, każda prop, każde zdarzenie mają swoje typy w TS.
JSX → JavaScript — co robi kompilator
// ══ JSX (piszesz w .tsx) ══════════════════════
const el = (
  <div className="box">
    <h1>{title}</h1>
    <p style={{ color: "red" }}>Treść</p>
  </div>
);

// ══ CO PRODUKUJE KOMPILATOR (React 17-) ═══════
const el = React.createElement(
  "div", { className: "box" },
  React.createElement("h1", null, title),
  React.createElement("p", { style: { color: "red" } }, "Treść")
);
// React 18+ (new JSX transform): importuje automatycznie
// z "react/jsx-runtime" — nie musisz importować React ręcznie

// ══ JSX vs HTML — ważne różnice ═══════════════
// HTML: class         →  JSX: className
// HTML: for           →  JSX: htmlFor
// HTML: onclick       →  JSX: onClick  (camelCase!)
// HTML: style="..."   →  JSX: style={{ }} (obiekt!)
// HTML: <br>          →  JSX: <br />  (musi być zamknięty)
// HTML: <!-- -->      →  JSX: {/* komentarz */}
// HTML: tabindex      →  JSX: tabIndex
// HTML: readonly      →  JSX: readOnly
// HTML: colspan       →  JSX: colSpan

// ══ WYRAŻENIA W JSX — tylko w {} ══════════════
const jsx = (
  <div>
    {2 + 2}                    // liczby i wyrażenia
    {name.toUpperCase()}       // wywołania funkcji
    {isOk && <span>OK</span>}   // warunkowe (uważaj na 0!)
    {items.map(i => (
      <li key={i.id}>{i.name}</li>  // key wymagany w mapie!
    ))}
  </div>
);
.tsx — typy elementów JSX, Fragment, renderowanie warunkowe
// ══ WYMOGI PLIKU .TSX ════════════════════════
// 1. Rozszerzenie MUSI być .tsx (nie .ts)
// 2. tsconfig.json: "jsx": "react-jsx"
// 3. Jeden root element lub Fragment

// ══ TYPY ELEMENTÓW JSX ═══════════════════════
import type { ReactNode, ReactElement } from "react";

// ReactNode — wszystko co React może wyrenderować
// string | number | boolean | null | undefined
// | ReactElement | ReactNode[]
// Użyj dla prop children

// ReactElement — konkretny element JSX (<div> itp.)
// Bardziej restrykcyjny — nie przyjmie stringa ani null

// JSX.Element — stary alias dla ReactElement, unikaj

// ✅ Bezpieczne opcje:
{count > 0 && <List />}      // porównanie boolean
{count ? <List /> : null}    // ternary z null
{!!count && <List />}        // podwójna negacja → boolean

// null, undefined, false → nic nie renderuje
// 0, "" → RENDERUJĄ SIĘ — pułapka!
Pułapka z && i liczbami {list.length && <Items />} — gdy list.length === 0, JSX renderuje "0" na stronie zamiast nic. Zawsze używaj: {list.length > 0 && <Items />} albo {list.length ? <Items /> : null}. Dotyczy każdej wartości numerycznej w warunkowym renderowaniu.

function Form() {
  // onChange — React.ChangeEvent<HTMLElement>
  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    console.log(e.target.value);      // string ✅
    console.log(e.target.checked);    // boolean (dla checkbox)
  };

  // onClick — React.MouseEvent<HTMLElement>
  const handleClick = (e: React.MouseEvent<HTMLButtonElement>) => {
    e.preventDefault();
    e.clientX;  // pozycja kursora ✅
  };

  // onSubmit — React.FormEvent<HTMLFormElement>
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
  };

}

React Hooks z TypeScript
useState, useEffect, useCallback, useMemo, useContext, custom hooks
Każdy hook ma swoje typy. useState inferuje typ z wartości początkowej — ale gdy inicjalizujesz null, musisz podać typ jawnie. Custom hook musi zaczynać się od use i zwracać dobrze oztypowaną wartość. Stale closures w useEffect to jedna z najczęstszych pułapek.
useState, useReducer, useContext — typy
// ══ USESTATE ══════════════════════════════════
const [count, setCount] = useState(0);          // infer: number
const [name,  setName]  = useState("");          // infer: string
const [flag,  setFlag]  = useState(false);       // infer: boolean

// Gdy może być null — jawny typ!
const [user, setUser] = useState<User | null>(null);
const [data, setData] = useState<string[]>([]);   // nie infer z []

// Functional updater — nowy stan zależy od starego
setCount(prev => prev + 1);    // prev: number — bezpieczne

// ══ USEREDUCER ════════════════════════════════
type Action =
  | { type: "increment" }
  | { type: "decrement" }
  | { type: "reset"; payload: number };

function reducer(state: number, action: Action): number {
  switch(action.type) {
    case "increment": return state + 1;
    case "decrement": return state - 1;
    case "reset":     return action.payload; // payload dostępny ✅
  }
}
const [count, dispatch] = useReducer(reducer, 0);

// ══ USECONTEXT ════════════════════════════════
type AuthCtx = { user: User | null; logout: () => void };
const AuthContext = createContext<AuthCtx | null>(null);

// Custom hook z guard — nigdy nie zwróci null
function useAuth(): AuthCtx {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be inside AuthProvider");
  return ctx; // TS wie: nie null ✅
}
useEffect, useCallback, useMemo, custom hook
// ══ USEEFFECT — stale closure pułapka ════════
const [count, setCount] = useState(0);

useEffect(() => {
  const id = setInterval(() => {
    // ❌ count zawsze = 0 — stale closure!
    // Efekt "zapamiętał" count=0 z pierwszego render
    setCount(count + 1); // zawsze 1
  }, 1000);
  return () => clearInterval(id);
}, []); // pusta deps = closure zamraża count

// ✅ Functional updater — zawsze aktualny stan
setCount(prev => prev + 1); // prev = aktualny count

// ══ USECALLBACK — stabilna referencja funkcji ═
const handleSubmit = useCallback(
  (data: FormData) => {
    submitForm(data);
  },
  [submitForm]  // zmieniaj callback gdy submitForm się zmieni
); // Typ inferowany z funkcji — nie musisz podawać jawnie

// ══ USEMEMO — zapamiętaj wynik obliczeń ═══════
const sortedUsers = useMemo(
  () => [...users].sort((a, b) => a.name.localeCompare(b.name)),
  [users]
); // User[] — inferowany z wartości zwracanej

// ══ CUSTOM HOOK — z generykiem ════════════════
function useLocalStorage<T>(key: string, initial: T) {
  const [value, setValue] = useState<T>(() => {
    const stored = localStorage.getItem(key);
    return stored ? (JSON.parse(stored) as T) : initial;
  });

  const set = useCallback((v: T) => {
    setValue(v);
    localStorage.setItem(key, JSON.stringify(v));
  }, [key]);

  return [value, set] as const; // as const → tuple nie array
}
const [theme, setTheme] = useLocalStorage<"light" | "dark">("theme", "light");
Custom hook — zasady TypeScript Hook musi zaczynać się od use (React tego wymaga). Gdy zwracasz tuple (np. [value, setter]), dodaj as const — inaczej TS inferuje (string | Function)[] zamiast precyzyjnego [string, (v: string) => void]. Typuj jawnie zwracaną wartość hooków publicznych — lepsze DX.

Pułapki, triki & senior patterns
Klasyczne błędy, ??, ?., mutacja state, key, Rules of Hooks
Tutaj mieszkają błędy które zjadają godziny. Mutacja state bez nowej referencji, złe key w listach, stale closures, reguły hooków. Oraz triki seniorów: branded types, discriminated unions jako jedyne źródło prawdy o stanie.
Operatory TS — ??, ?., !, różnice od JS
// ══ OPTIONAL CHAINING — ?. ════════════════════
const city  = user?.address?.city;      // undefined jeśli brak
const first = arr?.[0];                 // optional element
const res   = callback?.();             // optional call
const len   = str?.length ?? 0;        // chain z ??

// ══ NULLISH COALESCING — ?? ════════════════════
const name = user.name ?? "Anonim";   // tylko null/undefined
const port = config.port ?? 3000;

// RÓŻNICA od || (OR):
const a = 0  || "default";  // ➜ "default"   (0 jest falsy!)
const b = 0  ?? "default";  // ➜ 0           (0 nie jest null)
const c = "" || "default";  // ➜ "default"   ("" jest falsy!)
const d = "" ?? "default";  // ➜ ""          ("" nie jest null)

// ══ NON-NULL ASSERTION — ! ════════════════════
const el = document.getElementById("app")!;
// Mówisz TS: "wiem że nie jest null"
// Jeśli się mylisz → runtime error. Używaj oszczędnie.

declare const __brand: unique symbol;
type Brand<T, B> = T & { [__brand]: B };

type UserId    = Brand<string, "UserId">;
type ProductId = Brand<string, "ProductId">;

function getUser(id: UserId) { /* ... */ }
const pid = "p-123" as ProductId;
getUser(pid);  // ❌ błąd — nie możesz pomylić ProductId z UserId

// ══ MUTACJA STATE — nigdy! ════════════════════
// ❌ Mutacja nie powoduje re-renderu

  prev.push(newUser); // mutuje oryginał
